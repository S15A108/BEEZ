# 191번 회의→문서 수정안 재사용 탐색

`reuse_probe.py`는 **제품 경로나 계약 구현이 아닌 합성 자료·가짜 모델을 이용한 탐색용 스크립트**다. 190 회의 분석 결과를 가상으로 확인한 뒤, dev에 병합된 138 입력 변환 → 191 연결부 → 137 문서 수정안 생성 함수를 차례로 호출한다. 결정 승인·회의 ID와 근거 발언의 실제 저장은 시험하지 않는다.

137과 138은 dev에 병합됐다. 해당 변경이 포함된 작업 사본의 `ai/`에서 실행한다.

```powershell
python -m evaluations.meeting_revision_191.reuse_probe
```

실제 GMS 호출이나 저장은 없다. 모델이 만든 문자열을 검증된 결정으로 바로 사용하는 방식은 합의된 계약이 아니다. 이 샘플은 가상의 회의 결정이 이미 확인되었다고 **가정**해 전달한다. 잘못된 문서 버전·미선택 블록·없는 근거도 거부되는지 확인한다.

회의 정리의 결정에는 발언별 근거가 없다. 제품 경로에서는 사용자가 결정과 그 근거 발언을 명시적으로 선택하고 BE가 회의·문서 스냅샷과 권한을 검증한 후 AI 브리지를 호출한다. AI 브리지 자체는 실제 확인·권한·DB 저장 여부를 알 수 없다.

## 실제 모델 스모크 테스트

아래 명령은 유료 GMS 요청을 수행하며 지정된 env 파일에서 키를 읽는다. 테스트 자료는 모두 가상의 회의와 문서이다.

```powershell
python -m evaluations.meeting_revision_191.live_summary_smoke --env-file <env-file>
python -m evaluations.meeting_revision_191.live_smoke --env-file <env-file>
python -m evaluations.meeting_revision_191.live_chain_smoke --env-file <env-file>
```

권한, 보관 기간, 알림 대상의 세 가지 단순한 결정을 각각 테스트한다. 정리 테스트는 결정에 기대 키워드가 있는지, 수정 테스트는 선택한 문단에 기대 키워드가 들어가고 앞뒤 문단이 보존되는지 확인한다. 연결 테스트는 별도의 가상 회의 정리에서 얻은 결정을 확인됐다고 가정한 뒤 실제 모델을 다시 호출해 문서 수정까지 이어지는지 본다. 실제 사용자가 결정을 확인했는지, DB 저장이나 UI가 동작하는지, 복잡한 회의의 정확도까지 확인하는 평가는 아니다.
