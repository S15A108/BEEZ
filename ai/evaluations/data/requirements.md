# 나래 문서 업로드 요구사항

이 요구사항은 실험용 프로젝트 101의 현재 승인 버전 202를 나타낸다. 과거 버전의 수치와 초안의 수치는 현재 정책의 근거가 아니다.

## 파일 크기

단일 파일 업로드 한도는 30 MB이며, 초과하면 HTTP 413을 반환한다.

한도는 개별 파일마다 적용한다. 한 번에 여러 파일을 보낼 때 전체 요청의 합계 한도는 이 문서에서 정의하지 않는다. 파일을 압축했다고 해서 한도를 늘려 주지 않는다. 클라이언트 표시 단위와 서버 바이트 계산식의 세부 변환은 후속 계약에서 정한다. 제한을 초과한 파일을 일부만 저장해서 성공으로 응답하지 않는다.

## 재시도

색인 실패 시 원문 버전은 보존하고, 활성 프로젝트 멤버가 재시도할 수 있다.

재시도는 동일 실행의 성공 결과를 중복 저장하는 동작과 구분한다. 새로운 실행의 결과를 반영하기 전에 현재 시도 번호를 대조한다. 늦게 도착한 이전 결과가 최근 성공 결과를 덮어쓰면 안 된다. 권한이 사라진 멤버는 예전에 업로드한 파일이라도 재시도를 실행할 수 없다.

## 상태 표시

| 원문 상태 | 색인 상태 | 화면 안내 |
| --- | --- | --- |
| 준비됨 | 대기 | 검색 준비 중 |
| 준비됨 | 실행 중 | 검색 준비 중 |
| 준비됨 | 실패 | 재시도 가능 |
| 준비됨 | 완료 | 승인 범위에서 검색 가능 |

원문 수신 성공과 검색 준비 완료를 서로 다른 상태로 표시한다. 작업자가 문서 일부의 벡터만 저장했을 때 완료로 표시하지 않는다. 사용자가 직접 수정한 설계 항목은 색인 작업이 임의로 교체하지 않는다.

## 감사 기록

업로드와 재시도의 실행 식별자, 대상 버전 및 처리 결과를 기록한다. 원문과 인증 비밀값을 일반 오류 로그에 출력하지 않는다. 이 문서는 로그 보관 기간을 확정하지 않는다. 운영자가 보관 기간을 물으면 근거가 없다고 안내해야 한다.
