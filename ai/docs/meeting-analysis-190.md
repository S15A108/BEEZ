# 회의 질문·회의록 분석 (#190)

`POST /v1/bee/meeting-analysis`는 BE가 권한과 현재 입력을 확인한 뒤 전달한 회의 기록과 승인 설계를 분석한다. `QUESTIONS`는 확인할 질문과 미결 사항, `MINUTES`는 요약·결정·미결 사항·후속 행동을 반환한다. 이 API는 문서를 수정하거나 결정을 승인하거나 결과를 DB에 저장하지 않는다.

```text
BE: 회의 권한 확인 및 텍스트 기록·승인 설계 조회
  → AI: 내부 토큰 확인 → 입력 범위 검증 → 공통 LLM 호출
  → AI: 결과 형식과 출처·담당자 범위 확인 → 결과와 usage 반환
  → BE: 결과 표시·저장 및 사용량 기록 (후속 연동)
```

- 회의 내용과 승인 설계 본문은 명령이 아닌 분석 데이터로 취급하도록 모델에 지시한다. 모델 응답은 별도로 형식·입력 범위를 검증한다.
- 승인 설계의 출처 정보는 위치가 비어 있어도 입력으로 보존한다. 다만 저장된 위치가 실제 원문과 현재 기준에 맞는지 BE가 확인했다는 정보가 없으므로 모든 설계 출처는 미확인 참고 정보다. 현재는 `result.sources`에 확인된 인용을 내보내지 않으며, 모델이 출처를 반환하면 오류로 처리한다. BE가 확인된 원문 근거를 전달하는 계약을 정하고 연동한 뒤 인용을 지원해야 한다.
- 후속 행동의 담당자는 입력 회의 기록의 `author_member_id`에 있는 경우만 허용하며, 알 수 없으면 생략한다. 이 검사는 출처의 의미적 타당성이나 실제 참가자 권한을 확정하지 않는다.
- `request_key`는 BE 요청 추적용이고, `llm-meeting-<UUID>`는 모델 호출별 사용량 키다. 실패나 잘못된 모델 출력도 시작된 호출의 사용량을 반환한다.
- 모델 호출 예산은 15초로, 현재 BE 공통 AI 클라이언트 기본 읽기 제한 20초에 여유를 둔다. 예산은 모델 호출을 감싸며 입력 파싱·응답 전송 등 전체 HTTP 시간을 보장하지 않는다. BE 연동 시 실제 배포 설정과 요청 단위 예산을 함께 맞춰야 한다.
- 입력은 텍스트 회의 기록이다. 음성 업로드나 전사는 구현하지 않는다.
- `SUMMARY`, 수정 요청 및 문서 변경안은 문서상 수정안 요청이고 #191과 관계가 있어 현재 `422 invalid_ai_input`으로 구분한다. 회의 결과 저장·공개 API는 BE 담당 작업과 연동해야 한다.
- AI-A08 예시에는 `sources`가 있지만 공통 스키마 표에는 없어 예시를 기준으로 빈 배열을 반환한다. 회의 발언별 결정 근거 ID를 표현하는 확정 계약이 없어, 현재는 요약 문장에 근거를 설명하도록 요청할 뿐 출처 연결을 기계적으로 보증하지 않는다. 자유 텍스트에서 위치가 언급되지 않는 것까지 프로그램으로 보증하지는 못한다. 최종 응답 형태는 BE와 합의가 필요하다.

예시와 실제 모델 점검은 [회의 분석 평가](../evaluations/meeting_analysis/README.md)를 참고한다.
