# 4. 시연 시나리오

> 이 시나리오는 **개발 서버(<https://dev.beez.ai.kr>)에 미리 만들어 둔 시연 프로젝트 6개**로 진행합니다. 새로 클론해 띄운
> 서버에는 이 프로젝트들이 없으므로, 같은 화면을 보려면 개발 서버에 시연 계정으로 로그인하세요.
> 버튼 이름과 위치는 2026-11-17 화면 기준입니다.

## 4-0. 시연 개요

**전하려는 것**: 팀원이 각자 AI 에이전트로 개발해도, 팀이 승인한 설계 하나를 기준으로 일하게 된다.

시연 예제는 "예약 서비스"를 만드는 2인 팀(팀장 **전진**, 백엔드 담당 **백엔드진**)입니다. 프로젝트 전체 진행을 3분 안에 보일 수
없어서, 같은 프로젝트를 날짜별(D+0~D+6)로 미리 진행해 둔 프로젝트 6개를 씁니다. 3D 도시의 건물 하나가 그날의 프로젝트입니다.

| 단계 | 프로젝트(건물) | 보여 주는 것 |
| --- | --- | --- |
| ① 설계 확정 | D+0 설계 | 승인된 문서 4개로 설계 초안을 만들고, 팀장이 승인해 첫 기준(v1)을 발행합니다 |
| ② 착수 검증 | D+3 착수 | 에이전트가 직접 작업 계획을 올리고, 설계와 맞아 검사를 통과합니다 |
| ③ 충돌 감지 | D+4 충돌 | 다른 팀원의 에이전트가 같은 부분을 다르게 바꾸려 해서 "합의 필요"로 막힙니다 |
| ④ 회의와 결정 | D+4 회의 | 사람이 회의에서 정하고, 비비가 정리해 변경 제안으로 올립니다 |
| ⑤ 승인과 전파 | D+5 승인 | 변경이 영향을 주는 작업을 확인하고 승인해 새 기준(v2)을 발행합니다. 영향받는 작업은 다시 검사받게 됩니다 |
| ⑥ 재검증 | D+6 재개 | 두 작업이 새 기준에 맞게 계획을 고쳐 다시 통과합니다 |

## 4-1. 사전 준비

| 항목 | 내용 |
| --- | --- |
| 접속 주소 | <https://dev.beez.ai.kr> |
| 계정 | 팀장 계정. 아이디와 비밀번호는 제출 채널로 따로 전달합니다 |
| 브라우저 | Chrome, 창 폭 1024px 이상(좁으면 화면이 나오지 않음), 확대 100%, 전체 화면(F11) |
| 탭 | 아래 7개(도시 1개 + 단계별 프로젝트 6개)를 순서대로 열어 둡니다. 발표 중에는 `Ctrl+Tab`으로 넘깁니다 |
| 에이전트 | 시연 PC에 Claude Code를 설치하고, 팀장 계정으로 발급한 토큰으로 BEEZ를 연결해 둡니다([연결 매뉴얼](../docs/guides/agent-connection.md)) |

| 2 | D+0 설계 사무실 | 오른쪽 가이드 3단계에 `[설계 초안 만들기]`가 보이게 |
| 3 | D+3 착수의 작업 현황 | |
| 4 | D+4 충돌의 작업 현황 | `[팀 전체]` → T-2 "예약 취소 내역 구분" 선택 |
| 5 | D+4 회의의 회의실 | |
| 6 | D+5 승인의 변경 제안 CP-36, **영향** 탭 | |
| 7 | D+6 재개의 작업 현황 | `[팀 전체]` |

**발표 2분 전**: 터미널에서 `claude`를 켜고 아래 요청을 보냅니다. 1분 30초쯤 뒤 탭 3에 "내 예약 목록에 예약 상태 표시 · 계획
통과"가 뜨는지 확인합니다.

```text
내 예약 목록 API에 예약 상태를 넣으려고 해. BEEZ에서 승인 설계를 읽고, 작업 제목을 "내 예약 목록에 예약 상태 표시"로 해서
계획을 등록하고 검증까지만 진행해. 계획: GET /api/reservations/me 응답의 각 예약에 status 필드를 문자열로 추가한다.
값은 "RESERVED" 또는 "CANCELLED"다. API 명세를 바꾸는 계획이니 그 API 설계 항목을 CHANGES로 참조해.
계획은 네가 정하고 나에게 묻지 마. 작업 시작 보고와 코드 작성은 하지 마.
```

## 4-2. 진행

### 도입 (0:00–0:15) · 탭 1 3D 도시

| 순서 | 실행 | 화면에서 보이는 것 |
| --- | --- | --- |
| 1 | 마우스로 도시를 천천히 돌립니다 | 단계별 프로젝트 6개가 건물로 보입니다 |
| 2 | `Ctrl+Tab` | 탭 2로 이동 |

### ① 설계 확정 (0:15–0:35) · 탭 2 D+0 설계

| 순서 | 실행 | 화면에서 보이는 것 |
| --- | --- | --- |
| 1 | 오른쪽 가이드 3단계의 "문서 4종 승인 4/4"를 가리킵니다 | 기획안·요구사항·ERD·API 명세 모두 승인 |
| 2 | 3단계 `[설계 초안 만들기]` 클릭 | 기획 분석 창. 위쪽 탭 "보완 질문"·"설계 항목 초안" |
| 3 | 오른쪽 위 `[검토한 설계 승인·발행]` 클릭 → 칸에 `승인` 입력 → `[승인하고 기준 발행]` | 기준 v1 발행 |
| 4 | 창을 닫고(오른쪽 위 X) 왼쪽 위 프로젝트 이름 아래를 가리킵니다 | "시작 전" → "기준 v1" |

> 누르지 않을 것: 보완 질문 답변 칸과 다른 탭. 발행이 오류를 내면 탭 3으로 넘어갑니다(D+3 제목 옆 '기준 v1'이 같은 결과).

### ② 착수 검증 (0:35–0:55) · 탭 3 D+3 착수

| 순서 | 실행 | 화면에서 보이는 것 |
| --- | --- | --- |
| 1 | 내 작업의 "내 예약 목록에 예약 상태 표시" 카드 클릭 | 에이전트가 MCP로 직접 등록한 작업 |
| 2 | 진행 단계의 "계획 검증 · 통과"를 가리킵니다 | 계획이 승인된 설계와 맞아 통과 |

> 카드가 없거나 검증 중이면 `Esc` → `4`, 또는 탭 4에서 T-1 카드를 대신 엽니다.

### ③ 충돌 감지 (0:55–1:20) · 탭 4 D+4 충돌

| 순서 | 실행 | 화면에서 보이는 것 |
| --- | --- | --- |
| 1 | 왼쪽 T-2 카드의 "합의 필요"를 가리킵니다 | 백엔드 에이전트가 같은 status 필드를 숫자로 넣으려는 계획 |
| 2 | 오른쪽을 끝까지 내려 빨간 상자를 가리킵니다 | "설계와 계획의 검증 결과 · 합의 필요" — 같은 설계 항목을 다른 작업이 이미 바꾸는 중 |
| 3 | `Esc` → 숫자 키 `3` | 회의실. 참여자 "전진 · 백엔드진", 노란 줄 "정할 것" |

### ④ 회의와 결정 (1:20–2:10) · 탭 5 D+4 회의

| 순서 | 실행 | 화면에서 보이는 것 |
| --- | --- | --- |
| 1 | 대화 칸 맨 위 `[앞의 대화 2개]`를 펼치고 천천히 내립니다 | 백엔드는 숫자, 팀장은 문자열을 고른 이유 |
| 2 | "팀장으로 정리합니다"로 시작하는 발언을 가리킵니다 | 사람이 문자열로 결정 |
| 3 | 위쪽 단계 표시 "2 비비 정리"를 가리킵니다 | 비비가 대화를 정리 |
| 4 | 오른쪽 위 `[회의 끝내기]` 클릭 | 정리 카드: 충돌 → 결정, 바뀔 문서의 '지금'·'바뀐 뒤' |
| 5 | `[회의 끝내고 변경 제안 만들기]` 클릭 → 위로 올립니다 | 노란 띠 "회의를 끝내고 변경 제안을 올렸어요" |

> 누르지 않을 것: `[비비에게 정리 요청]`, `[회의 수정 초안 만들기]` (AI를 다시 불러 정리가 새로 생깁니다).

### ⑤ 승인과 전파 (2:10–2:45) · 탭 6 D+5 승인

| 순서 | 실행 | 화면에서 보이는 것 |
| --- | --- | --- |
| 1 | 영향 탭의 "확인된 관계" T-1, T-2를 가리킵니다 | 이 변경이 영향을 주는 작업 두 개 |
| 2 | 아래로 내려 `[승인하고 기준 v2 발행]` 클릭 | "다시 검증이 필요한 작업 2개", "대기로 바뀔 작업 1개" |
| 3 | 사유 칸에 `영향 탭에서 T-1, T-2 두 작업에 영향이 가는 것을 확인함` 입력 → `[사유 남기고 기준 v2 발행]` | "새 기준을 발행했어요" |

> 누르지 않을 것: `[다시 분석]`, `[영향 다시 분석]`.

### ⑥ 재검증 (2:45–3:00) · 탭 7 D+6 재개

| 순서 | 실행 | 화면에서 보이는 것 |
| --- | --- | --- |
| 1 | 제목 아래 "기준 v2"를 가리킵니다 | 새 기준 |
| 2 | 왼쪽 두 카드의 "계획 통과"를 차례로 가리킵니다 | 두 에이전트가 새 기준으로 계획을 고쳐 다시 통과, 팀장 작업 재개 |

## 4-3. 시간이 부족할 때

| 남은 시간 | 줄이는 법 |
| --- | --- |
| 2분 | ①은 "승인된 문서가 기준 v1입니다" 한 문장으로 끝내고, ⑥은 ⑤ 끝에 이어서 말합니다 |
| 1분 | ③, ⑤, ⑥만 합니다. ④는 "회의에서 팀장이 문자열로 정했습니다" 한 문장 |

③~⑤(충돌을 찾고, 사람이 정하고, 새 기준을 알리는 부분)는 시간이 없어도 꼭 보여 주세요.
