# 4. 시연 시나리오

이 시나리오는 개발 서버(<https://dev.beez.ai.kr>)에 미리 만들어 둔 시연 프로젝트 6개로 진행합니다. 새로 클론해 띄운
서버에는 이 프로젝트들이 없으니, 같은 화면을 보려면 개발 서버에 시연 계정으로 로그인하거나 시연 덤프를 PC에 복원하세요
([3-2](03-db-dump.md#3-2-덤프로-복원하기-pc에서)). 버튼 이름과 위치는 2026-11-17 화면 기준입니다.

## 4-0. 시연 개요

전하려는 것: 팀원이 각자 AI 에이전트로 개발해도, 팀이 승인한 설계 하나를 기준으로 일하게 된다.

시연 예제는 예약 서비스를 만드는 2인 팀입니다. 팀장은 전진 계정, 백엔드 담당은 시연용으로 만든 백엔드진 계정입니다. 프로젝트 전체 진행을 3분 안에 보일 수
없어서, 같은 프로젝트를 날짜별(D+0~D+6)로 미리 진행해 둔 프로젝트 6개를 씁니다. 3D 도시의 건물 하나가 그날의 프로젝트입니다.

화면에 나오는 **비비**는 BEEZ 안의 AI 도우미입니다. 문서를 검토하고, 작업 계획을 설계와 비교해 검사하고, 회의를 정리합니다.

| 단계 | 프로젝트(건물) | 보여 주는 것 |
| --- | --- | --- |
| ① 설계 확정 | D+0 설계 | 승인된 문서 4개로 설계 초안을 만들고, 팀장이 승인해 첫 기준(v1)을 발행합니다 |
| ② 착수 검증 | D+3 착수 | 에이전트가 직접 작업 계획을 올리고, 설계와 맞아 검사를 통과합니다 |
| ③ 충돌 감지 | D+4 충돌 | 다른 팀원의 에이전트가 같은 부분을 다르게 바꾸려 해서 "합의 필요"로 막힙니다 |
| ④ 회의와 결정 | D+4 회의 | 사람이 회의에서 정하고, 비비가 정리해 변경 제안으로 올립니다 |
| ⑤ 승인과 전파 | D+5 승인 | 변경이 영향을 주는 작업을 확인하고 승인해 새 기준(v2)을 발행합니다. 영향받는 작업은 다시 검사받게 됩니다 |
| ⑥ 재검증 | D+6 재개 | 두 작업이 새 기준에 맞게 계획을 고쳐 다시 통과합니다 |

## 4-1. 사전 준비

### 환경

| 항목 | 내용 |
| --- | --- |
| 접속 주소 | <https://dev.beez.ai.kr> |
| 계정 | 개발 서버는 팀장 계정(로그인 이메일과 비밀번호는 제출 채널로 따로 전달합니다). PC에 덤프를 복원했다면 [3-2](03-db-dump.md#3-2-덤프로-복원하기-pc에서)의 시연 계정과 비밀번호 `beez-demo-2026`을 씁니다 |
| 브라우저 | Chrome, 창 폭 1024px 이상(좁으면 화면이 나오지 않습니다), 확대 100%, 전체 화면(F11) |

### 에이전트 연결

시연 PC에 Claude Code를 설치하고, **D+3 착수 프로젝트**의 토큰으로 BEEZ를 연결합니다. 에이전트가 계획을 등록하는 곳이
이 프로젝트라서, 다른 프로젝트의 토큰으로 연결하면 ②에서 카드가 나타나지 않습니다.

1. 도시에서 "D+3 착수" 건물을 클릭해 들어갑니다.
2. 오른쪽 위의 톱니바퀴(설정) 버튼을 누르고, 설정 창 왼쪽 메뉴의 **내 에이전트 관리**에서 토큰을 발급합니다.
3. 시연에 쓸 빈 폴더를 만들어(`mkdir beez-demo && cd beez-demo`) 그 안에서 화면에 나온 연결 명령을 실행합니다.
   이어서 발급 화면 3단계 "CLAUDE.md에 작업 절차 붙여넣기"의 `[CLAUDE.md 내용 복사]`를 누르고, `beez-demo` 폴더에
   `CLAUDE.md` 파일을 만들어 붙여 넣습니다. 에이전트가 이 파일을 읽고 BEEZ 작업 순서를 따릅니다.

   ```bash
   claude mcp add --transport http beez https://dev.beez.ai.kr/mcp --header "Authorization: Bearer <토큰>"
   ```

4. 같은 폴더(`beez-demo`)에서 `claude`를 켜고 `/mcp`를 입력해 `beez`가 connected인지 확인합니다.

한 계정은 프로젝트마다 연결 하나만 유지됩니다. 발표 중에는 다른 터미널이나 PC에서 같은 계정으로 `claude`를 켜지
마세요. 나중에 연결한 쪽만 남고 시연 터미널의 연결은 끊깁니다.

### 탭 열어 두기

프로젝트 안에서는 숫자 키로 업무 창을 엽니다. 브라우저에서 프로젝트에 처음 들어가면 환영 창이 뜨고, 이 창이 떠 있는 동안에는 숫자 키가 동작하지 않으니 `Esc`로 닫고 시작하세요. `1` 공용 문서함, `2` 변경 제안, `3` 회의실, `4` 작업 현황이고, `Esc`로 닫습니다.
아래 7개 탭을 순서대로 만들어 둡니다. 탭마다 새 탭에서 <https://dev.beez.ai.kr>을 열면 로그인된 도시 화면이 나오고, 거기서 시작합니다.

| 탭 | 화면 | 만드는 법 |
| --- | --- | --- |
| 1 | 3D 도시 | 로그인 직후 화면 그대로 둡니다 |
| 2 | D+0 설계 사무실 | "D+0 설계" 건물 클릭. 오른쪽 가이드 3단계에 `[설계 초안 만들기]`가 보이는지 확인합니다 |
| 3 | D+3 착수의 작업 현황 | "D+3 착수" 건물 클릭 → `4` |
| 4 | D+4 충돌의 작업 현황 | "D+4 충돌" 건물 클릭 → `4` → `[팀 전체]` → T-2 "예약 취소 내역 구분" 카드 클릭 |
| 5 | D+4 회의의 회의실 | "D+4 회의" 건물 클릭 → `3` |
| 6 | D+5 승인의 변경 제안 | "D+5 승인" 건물 클릭 → `2` → 변경 제안 CP-36 클릭 → 위쪽 **영향** 탭 |
| 7 | D+6 재개의 작업 현황 | "D+6 재개" 건물 클릭 → `4` → `[팀 전체]` |

발표 중에는 `Ctrl+Tab`으로 다음 탭으로 넘어갑니다.

### 발표 2분 전

시연 터미널의 `claude`에 아래 요청을 보냅니다. 1분 30초쯤 뒤 탭 3에 "내 예약 목록에 예약 상태 표시" 카드가 "계획 통과"로
뜨는지 확인합니다. 이 요청은 한 번만 보내세요. 다시 보내면 같은 작업이 하나 더 생깁니다.

```text
내 예약 목록 API에 예약 상태를 넣으려고 해. BEEZ에서 승인 설계를 읽고, 작업 제목을 "내 예약 목록에 예약 상태 표시"로 해서
계획을 등록하고 검증까지만 진행해. 계획: GET /api/reservations/me 응답의 각 예약에 status 필드를 문자열로 추가한다.
값은 "RESERVED" 또는 "CANCELLED"다. API 명세를 바꾸는 계획이니 그 API 설계 항목을 CHANGES로 참조해.
계획은 네가 정하고 나에게 묻지 마. 작업 시작 보고와 코드 작성은 하지 마.
```

### 리허설과 서버 장애 대비

①의 기준 발행, ④의 회의 끝내기, ⑤의 기준 v2 발행은 되돌릴 수 없습니다. 개발 서버에서 한 번 누르면 같은 화면을 다시
볼 수 없으니, 리허설은 시연 덤프를 PC에 복원한 환경([3-2](03-db-dump.md#3-2-덤프로-복원하기-pc에서))에서 하세요.
리허설이 끝나면 3-2를 다시 실행해 처음 상태로 돌리고, 아래 1, 3, 4번도 다시 합니다. 터미널을 새로 열었다면 AI 기능 설정(1번)이 사라져 있습니다.

개발 서버가 내려가 있을 때도 같은 방법으로 PC에서 시연할 수 있습니다. 이때는 아래를 다시 준비하세요.

1. PC에서 AI 기능을 켭니다([README "AI 기능 켜기"](../README.md#4-ai-기능-켜기)). 꺼져 있으면 ②가 동작하지 않습니다.
2. 탭은 <http://localhost:8088>에서 같은 방법으로 엽니다.
3. 에이전트를 다시 연결합니다. 연결 주소가 개발 서버에서 PC로 바뀌니, `beez-demo` 폴더에서 기존 연결을 지우고
   PC 화면에서 D+3 착수 프로젝트의 토큰을 새로 발급해 연결합니다.

   ```bash
   claude mcp remove beez
   claude mcp add --transport http beez http://localhost:8088/mcp --header "Authorization: Bearer <PC에서 받은 토큰>"
   ```

4. 덤프는 에이전트 요청을 보내기 전 상태라서, "발표 2분 전" 요청을 PC에서 다시 보냅니다.

| 2 | `Ctrl+Tab` | 탭 2로 넘어갑니다 |

### ① 설계 확정 (0:15~0:35, 탭 2: D+0 설계)

| 순서 | 실행 | 화면에서 보이는 것 |
| --- | --- | --- |
| 1 | 오른쪽 가이드 3단계의 "문서 4종 승인 4 / 4"를 가리킵니다 | 기획안, 요구사항, ERD, API 명세가 모두 승인된 상태 |
| 2 | 3단계의 `[설계 초안 만들기]` 클릭 | 기획 분석 창이 열리고, 위쪽에 "보완 질문"과 "설계 항목 초안" 탭이 보입니다 |
| 3 | 오른쪽 위 `[검토한 설계 승인·발행]` 클릭 → 입력 칸에 `승인` 입력 → `[승인하고 기준 발행]` 클릭 | 기준 v1이 발행됩니다 |
| 4 | 오른쪽 위 X로 창을 닫고, 왼쪽 위 프로젝트 이름 아래를 가리킵니다 | "시작 전"이 "기준 v1"로 바뀌어 있습니다 |
| 5 | `Ctrl+Tab` | 탭 3으로 넘어갑니다 |

보완 질문 답변 칸과 다른 탭은 누르지 않고 보기만 합니다. 답변 칸에 입력하면 저장된 답이 자동으로 바뀝니다. 발행에서 오류가 나면 바로 `Ctrl+Tab`으로 넘어가세요. 탭 3의 제목 옆
"기준 v1"이 같은 결과를 보여 줍니다.

### ② 착수 검증 (0:35~0:55, 탭 3: D+3 착수)

| 순서 | 실행 | 화면에서 보이는 것 |
| --- | --- | --- |
| 1 | 내 작업의 "내 예약 목록에 예약 상태 표시" 카드 클릭 | 에이전트가 MCP로 직접 등록한 작업입니다 |
| 2 | 진행 단계의 "계획 검증 · 통과"를 가리킵니다 | 계획이 승인된 설계와 맞아 통과했습니다 |
| 3 | `Ctrl+Tab` | 탭 4로 넘어갑니다 |

카드가 없거나 아직 검증 중이면 `Esc`로 작업 현황을 닫았다가 숫자 키 `4`로 다시 열어 봅니다. 그래도 없으면 탭 4로 넘어가
T-1 "내 예약 목록에 예약 상태 표시" 카드를 대신 열고 같은 설명을 합니다. 이 경우 ③을 시작할 때 T-2 카드를 다시 클릭합니다.

### ③ 충돌 감지 (0:55~1:20, 탭 4: D+4 충돌)

| 순서 | 실행 | 화면에서 보이는 것 |
| --- | --- | --- |
| 1 | 왼쪽 T-2 카드의 "합의 필요"를 가리킵니다 | 백엔드 담당의 에이전트가 같은 status 필드를 숫자로 넣으려는 계획입니다 |
| 2 | 오른쪽 상세를 끝까지 내려 빨간 상자를 가리킵니다 | "설계와 계획의 검증 결과 · 합의 필요". 같은 설계 항목을 다른 작업이 이미 바꾸는 중이라 막혔습니다 |
| 3 | `Esc`로 작업 현황을 닫고 숫자 키 `3` | 이 프로젝트의 회의실이 열립니다. 참여자 "전진 · 백엔드진"과 노란 줄 "정할 것"을 가리킵니다 |
| 4 | `Ctrl+Tab` | 탭 5(같은 회의가 더 진행된 D+4 회의 프로젝트)로 넘어갑니다 |

### ④ 회의와 결정 (1:20~2:10, 탭 5: D+4 회의)

| 순서 | 실행 | 화면에서 보이는 것 |
| --- | --- | --- |
| 1 | 대화 칸 맨 위 `[앞의 대화 2개]`를 눌러 펼치고 천천히 내립니다 | 백엔드 담당은 숫자, 팀장은 문자열을 고른 이유 |
| 2 | "팀장으로 정리합니다"로 시작하는 발언을 가리킵니다 | 사람이 문자열로 정했습니다 |
| 3 | 위쪽 단계 표시 "2 비비 정리"를 가리킵니다 | 비비가 대화를 정리했습니다 |
| 4 | 오른쪽 위 `[회의 끝내기]` 클릭 | "회의를 끝낼까요?" 화면에 무엇이 부딪혔고 무엇으로 정했는지, 바뀔 문서의 '지금'과 '바뀐 뒤'가 보입니다 |

### ⑤ 승인과 전파 (2:10~2:45, 탭 6: D+5 승인)

| 순서 | 실행 | 화면에서 보이는 것 |
| --- | --- | --- |
| 1 | 영향 탭의 "확인된 관계"에서 T-1, T-2를 가리킵니다 | 이 변경이 영향을 주는 작업 두 개 |
| 2 | 아래로 내려 오른쪽 아래 `[승인하고 기준 v2 발행]` 클릭 | 확인 화면에 "다시 검증이 필요해지는 검증 2개"와 "대기 · 재검증이 되는 작업 1개"가 보입니다 |
| 3 | 사유 칸에 `영향 탭에서 T-1, T-2 두 작업에 영향이 가는 것을 확인함` 입력 → `[사유 남기고 기준 v2 발행]` 클릭 → 화면을 위로 올립니다 | 활동 기록에 "새 기준으로 발행했어요"가 보입니다 |
| 4 | `Ctrl+Tab` | 탭 7로 넘어갑니다 |

`[다시 분석]`과 `[영향 다시 분석]`은 누르지 않습니다. AI를 다시 불러 영향 분석 결과가 바뀝니다. 승인에서 오류가 나면 탭 7로 넘어가, 제목 아래 "기준 v2"와 두 카드의 "계획 통과"를 가리키며 승인한 뒤의 모습이라고
설명합니다.

| 1 | 제목 아래 "기준 v2"를 가리킵니다 | 새 기준 |
| 2 | 왼쪽 두 카드의 "계획 통과"를 차례로 가리킵니다 | 두 에이전트가 새 기준에 맞게 계획을 고쳐 다시 통과했고, 팀장의 작업이 다시 진행 중입니다 |

## 4-3. 시간이 부족할 때

| 남은 시간 | 줄이는 법 |
| --- | --- |
| 2분 | ①은 "승인된 문서가 기준 v1입니다" 한 문장으로 끝내고, ⑥은 ⑤ 끝에 이어서 말합니다 |
| 1분 | ③, ⑤, ⑥만 합니다. ④는 "회의에서 팀장이 문자열로 정했습니다" 한 문장으로 대신합니다 |

③과 ⑤(충돌을 찾고 새 기준을 알리는 부분)는 시간이 없어도 꼭 화면으로 보여 주고, ④(사람이 정하는 부분)는 최소한 말로라도 이어 주세요.
