# 담당자 추천 실모델 가상 사례 평가 (S15P31A108-189)

2026-11-03에 GMS `gpt-6-luna`와 `json_schema` 응답 형식으로 수행했다. 모두 사람이 만든 가상 설계·작업·담당자이며 실제 프로젝트 자료는 사용하지 않았다. 대상 제품 코드는 PR #92의 `9b8e15f`이다. 모델 후보와 최종 담당자 목록, 이유와 출처, 사용량은 [가상 실행 결과 JSON](results/owner-recommendation-189-gms-2026-11-03.json)에 보존했다.

세 번의 실행에서 첫 실행은 4개, 이후 실행은 각각 5개 사례로 총 14회 호출했다. 첫 두 실행에서는 문서 본문이 자리표시자라 출처의 본문 일치 여부를 판단할 수 없었다. 마지막 실행에서는 가상 문서에 기준 응답 필드를 명시해 수동 대조했다. AI에 전달된 데이터는 승인 설계의 구조화 내용과 문서 출처 메타데이터이며, 문서 원문 검색이나 원문 전체 전달을 평가한 것은 아니다.

## 사례와 관찰

| 사례 | 기대 기준 및 관찰 |
| --- | --- |
| 필드명 변경, 간접 작업 설명이 짧음 | `userId`를 `memberId`로 변경하고 직접 담당자와 간접 작업 담당자를 검토 후보로 기대했다. 세 실행 모두 직접 담당자는 포함됐지만 간접 담당자는 빠졌다. 간접 작업도 모델 입력에 포함된 것을 확인했다. 다만 짧은 제목만으로 실제 API 연결을 확정할 수 없으므로, 이는 검토 후보 누락이라는 가상 기준과의 차이다. |
| 필드명 변경, 간접 작업 설명이 명확함 | 간접 작업 제목에 회원 조회 API 응답의 `userId`를 사용한다고 명시했다. 두 실행 모두 직접·간접 담당자를 추천했고 무관한 세 번째 담당자는 추천하지 않았다. 모델은 간접 작업의 설계 참조가 다른 항목이라 실제 연결 확인이 필요하다는 불확실성을 이유에 적었다. |
| 설명 문구만 변경 | 세 실행 중 두 번은 AI 작업 후보가 없었고, 마지막에는 계약은 동일하지만 문구의 의미가 넓어질 가능성을 확인하자는 AI 후보 1건을 냈다. 이 사례의 기대는 AI 후보 없음이다. 추가 후보는 이미 직접 참조로 추천된 담당자에 대한 것이었고 새 담당자를 만들지는 않았다. |
| 열린 작업 없음 | 세 실행 모두 담당자 추천과 직접 알림 후보가 비어 있었다. 모델은 설계 항목 수준의 불확실성은 반환했지만 `INSUFFICIENT_EVIDENCE`였고 담당자로 승격되지 않았다. |
| 문서 출처 없음 | 세 실행 모두 `INSUFFICIENT_EVIDENCE`로 AI 후보를 보류했다. 직접 참조로 확인된 담당자는 유지됐다. |

마지막 실행의 필드명 변경 이유는 기준 `userId`, 제안 `memberId`, 해당 작업 제목과 출처 메타데이터를 대조했다. 설명 문구 사례의 추가 후보는 의미가 확실히 바뀌었다고 단정하지는 않았지만, 문구만 달라진다는 이 사례의 기대와는 다르다. 직접 참조 담당자는 변경의 실제 영향도를 AI가 낮게 판단해도 보수적으로 추천되므로, 설명만 바뀐 사례의 최종 담당자 1명은 AI에 의한 추가 추천이 아니다.

AI 후보는 검토용이며 직접 참조 담당자만 알림 후보에 제공한다. 따라서 명확한 간접 작업에서 AI가 담당자를 찾아도 그 담당자가 자동 알림 후보에 추가되는 것은 아니다. `COMPLETED`나 테스트 통과는 모델이 모든 관련 담당자를 찾았다는 뜻이 아니다. 소수의 가상 사례와 각 2~3회 관찰만으로 운영 정확도나 반복 안정성을 추정할 수 없고, 실제 업무 사례에 대한 정답 구축과 별도 평가가 필요하다.

## 재실행

Docker, Java 21, AI 의존성이 설치된 Python과 테스트용 GMS 인증이 필요하다. 인증값은 저장소나 명령행에 적지 않고 실행 프로세스에 안전하게 주입한다. 실제 모델 호출과 비용이 발생한다. `backend/`에서 실행한다.

```powershell
$env:BEEZ_RUN_AI_E2E = "true"
$env:BEEZ_IMPACT_E2E_REAL_GMS = "true"
# BEEZ_IMPACT_E2E_GMS_KEY를 실행 환경에 안전하게 주입한다.
# 필요할 때 BEEZ_E2E_PYTHON에 Python 실행 파일 경로를 설정한다.
.\gradlew.bat integrationTest --no-daemon --rerun-tasks --tests "com.beez.backend.impactanalysis.ImpactBackendFastApiE2ETest.ownerRecommendationQualityAcrossSyntheticScenarios"
```

시험은 격리된 PostgreSQL, 별도 FastAPI, 백엔드 재분석·조회 HTTP API를 사용한다. JUnit의 `PASSED`는 호출과 안전 조건을 확인했다는 뜻이며 후보의 정확도 합격 판정이 아니다. 사례별 `OWNER_EVAL_JSON`은 `backend/build/test-results/integrationTest/`의 해당 테스트 XML `system-out`에서 확인하고, 기대 후보와 실제 후보 및 이유를 사람이 검토한다. `BEEZ_IMPACT_E2E_REAL_GMS`를 제거하면 테스트 대역으로 연결만 확인하며 실모델 품질 결과가 아니다.
