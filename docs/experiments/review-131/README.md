# 131 가상 사례 독립 검토 준비

이 폴더의 `blind-review.md`와 `review-form.json`은 기존 5개 가상 실측 입력을 사람이 검토할 수 있도록 준비한 **미완료 양식**이다. 검토자와 판단값을 기입하지 않았고, 이 자료를 만든 것만으로 독립 검토가 이뤄졌거나 모델 품질이 입증된 것은 아니다. 실제 BE 검색·권한·MCP와 운영 데이터는 평가하지 않는다.

검토자는 먼저 `blind-review.md`의 요청·후보·관계와 표시된 원문을 확인한다. 검토를 마치기 전에는 기존 fixture의 기대 라벨, 모의 선택, 실측 결과를 열지 않는다. 사례 이름도 정답을 암시할 수 있어 양식에서는 `CASE-01`~`CASE-05`로 표시했다. 이 절차는 실수를 줄이기 위한 것이며 접근 권한을 통제하거나 독립성을 증명하지 않는다.

`review-form.json`을 **별도 파일로 복사**하고 다음 값을 직접 기입한다.

- `reviewer`: 검토자 식별 문자열. 본인이 입력한 주장일 뿐 도구가 신원을 확인하지 않는다.
- 각 사례의 `uncertain`: 판단하지 못하면 `true`, 판단했으면 `false`. 판단 불가일 때 나머지 세 필드는 모두 `null`로 둔다.
- 판단한 사례의 `direct_item_ids`: 요청에 **직접 관련된** 설계 버전 ID 배열이다. 작업 참조나 관계만으로 포함할 항목은 직접 관련으로 표시하지 않는다. 없으면 `[]`다.
- `expected_evidence_ids`: 요청에 관련된 원문 ID 배열이다. 없으면 `[]`다.
- `no_match`: 직접 관련 설계와 원문이 모두 없다고 판단하면 `true`다. `TASK_PLAN` 참조만 포함되는 사례는 최종 설계 ID가 있어도 `true`일 수 있다. 판단하면 반드시 `true` 또는 `false`를 명시한다.

비교 도구는 검토자가 기입한 직접 관련 설계와 작업 참조를 시작점으로 확정·명시 `DEPENDS_ON` 관계를 **한 단계만** 확장해 최종 기대 설계 ID를 계산한다. 이는 기존 선택 함수 호출과 별도로 계산한다. `no_match`가 직접 관련 설계·원문 유무와 모순되면 비교를 거부한다.

`CASE-04`의 원문 후보는 실측 당시 별도 교체되어 다른 원문과 경쟁하지 않았다. 해당 사례로 일반적인 검색 품질을 추정하지 않는다. 모델이 보지 않은 문서를 사람이 확인할 수 있으므로, 라벨은 **당시 표시된 후보 집합**에 한정한다.

## 비교 실행

저장소 `ai` 디렉터리에서 아래 예시의 검토 파일과 출력 파일을 지정한다. 원본 실측과 검토 양식은 덮어쓰지 않는다. 이 도구는 네트워크나 모델을 호출하지 않는다.

```text
python -m evaluations.context_selection_blind_131 --fixture tests/fixtures/retrieval/context-selection-131.json --repository .. compare --review REVIEWED.json --measurement ../docs/experiments/results/S15P31A108-131-thresholds-2026-11-02.json --threshold 0.45 --output NEW_COMPARISON.json
```

`--threshold`를 생략하면 저장된 기본 임계값을 사용한다. 저장되지 않은 임계값의 선택을 추정하지 않는다. fixture·원문 파일과 **검토 양식에 연결된 현재 재구성 입력**의 해시, 정확한 5개 사례 집합, 후보 ID·중복, 명시적 판단을 확인하고 일치하지 않으면 비교를 중단한다. 사례 해시는 익명 번호와 재구성 입력이 나중에 바뀌어 엉뚱한 사례에 라벨을 적용하는 일을 막는다. 판단 불가 사례는 결과에서 `uncertain_skipped`로 표시한다.

기존 실측 JSON에는 사례별 입력 해시가 없으므로, 과거 측정과는 저장된 fixture SHA-256과 사례 ID 집합만 대조한다. 당시 입력을 구성한 코드와 버전은 별도로 확인해야 한다. 검토 양식의 입력 해시가 과거 공급자에 전달된 본문까지 증명하지는 않는다.

결과는 사람이 판단한 최종 ID와 저장된 최종 ID의 누락·추가 및 `NO_MATCH` 일치만 비교한다. 기존 실측에는 개별 후보 벡터·점수와 선택 이유가 없으므로 직접 매칭 정확도, 점수, 새 질의의 효과는 계산하지 않는다. 검토자 본인 입력·가상 사례·소규모 데이터라는 한계는 비교 뒤에도 그대로다.

비교 결과의 `dependency_status`는 `unverified`(입력에 전달된 관계의 미확인 표식이 있음), `none_reported`(버전 4 또는 5 측정에서 그 표식이 없음), `not_recorded`(이전 또는 아직 해석을 정의하지 않은 버전에서 표식이 없어 상태를 알 수 없음)로 구분한다. 버전 4는 확정 명시 관계의 대상·버전 미확인, 버전 5는 그 경우와 명시적 재확인 필요 관계를 포함한다. `NO_MATCH`는 별도로 비교하므로 두 표시가 동시에 있어도 판단이 가능하다. `none_reported`도 전달되지 않은 관계까지 검증했거나 BE 조회가 완전하다는 뜻은 아니다.

같은 fixture로 새 빈 자료가 필요하면 다음처럼 **새 경로**에 생성한다. 두 결과 파일은 기존 경로를 덮어쓰지 않는다.

```text
python -m evaluations.context_selection_blind_131 --fixture tests/fixtures/retrieval/context-selection-131.json --repository .. prepare --sheet NEW_SHEET.md --form NEW_FORM.json
```
