# 문서 파싱·검색 평가 계획 — 박상은 담당 범위

작성: 2026-10-24 · 범위 갱신: 2026-10-27 · 상태: C 모의·D 개발용 실측 수행, BE 통합 전 · 대상: #88, #89 및 관련 AI 응답 연동

[#88 상세 설계](../superpowers/specs/2026-10-24-document-parsing-design.md)는 필수 동작과 구현 경계를 정의한다. 이 문서는 방식별 효과를 비교하고 채택 여부를 결정하기 위한 평가 계획이다. 의미 검증 LLM 전수 적용·문맥 보강·색인 세대 구현을 새 MVP 필수 기능으로 확정하지 않는다. #130의 C 모의·D 개발용 결과는 [별도 평가 기록](document-rag-evaluation-S15P31A108-130.md)에 있으며, A/B와 실제 BE 통합 평가는 아직 수행하지 않았다.

현재 [개발 계획](../superpowers/plans/2026-10-26-document-rag-development.md)은 Markdown 4종 RAG 우선이다. **첫 MVP는 C(승인 버전 일관성)·D(검색 청킹과 답변)를 평가하고, A/B는 후속 설계 항목 추출을 도입할 때 실행한다.** OpenAPI JSON 검색 입력은 다음 단계이며 후보 추출 없이도 C/D에 새 입력 사례를 추가할 수 있다. YAML/DDL은 첫 평가 데이터에 필수로 요구하지 않는다.

작업 종료 범위는 2026-10-27 사용자 결정에 따라 나눈다. **#130은 AI 검증 도구·fixture·개발용 실측·인계 및 dev 병합으로 완료**하고, 실제 BE 저장/검색·DB/운영 경로 C/D 검증과 운영 자료/라벨 검토는 [BE 후속 #213](https://ssafy.atlassian.net/browse/S15P31A108-213) 및 관련 후속 작업에서 이어간다. 아래 MVP 전체 평가 계획을 #130 단일 티켓의 종료 조건으로 해석하지 않는다.

## 1. 범위와 공통 평가 조건

- A/B는 후속 추출·검증·분할 모듈을 평가한다. B는 #88의 추출 LLM 입력 분할이며 D의 검색 청크 성능 평가와 구분한다.
- C는 #89의 승인본 검색 및 AI 근거 사용을 평가한다. 승인 트랜잭션·검증 지점·응답 발행 정책은 BE·응답 담당자와 합의해야 한다. 그 전에는 모의 상태로 테스트 절차를 검증할 수 있다.
- 사람이 원문에서 정답 항목·행위자·조건·예외·원문 위치를 표시한다. 후보는 정상/원문과 모순/근거 없는 추가/판단 유보로 분류한다. 애매한 라벨은 합의하거나 판단 유보로 남기며 평가 LLM의 판정을 정답으로 사용하지 않는다.
- 시작 데이터는 기획·요구사항·API 명세·데이터 설계 Markdown 약 12개(종류별 3개)를 제안한다. 후속 A/B 실행 시 자연어 후보·긴 Markdown·표 사례를 충분히 포함하도록 구성한다. 정상·손상 fixture와 실제 모델 평가 자료를 구분한다.
- 프롬프트·한도를 조정하는 개발용 자료와 최종 평가 자료를 구분한다. 고정된 평가 자료에 맞춰 반복 튜닝한 결과를 독립 평가로 보고하지 않는다.
- 원문/text hash, 정답 버전, 코드·파서·프롬프트·모델 버전, 샘플링 설정, 토크나이저, 한도·overlap·재시도 설정을 실행 기록에 남긴다.
- 확률적 모델 경로는 같은 입력에서 우선 3회 반복하고, 비교군별 동일 조건을 적용한다. 고정 파서·기계적 검증은 같은 입력에서 동일 결과인지 별도 확인한다. 반복 횟수는 실행 전 고정하고 실제 횟수를 결과에 기록한다.
- 평균만 보고하지 않고 문서별 값·분자/분모·오류 건수·변동을 함께 남긴다. 소규모 표본의 차이를 일반적 성능 보장으로 확대하지 않는다.

## 2. 실험 A — 근거·의미 검증의 순효과

### 비교군과 절차

| 비교군 | 처리 |
| --- | --- |
| A1 | LLM 추출 후보, 후속 근거 검증 없음 |
| A2 | 동일 후보 + 스키마·블록 존재·인용 일치 검사 |
| A3 | A2 + 선택적 의미 검증 |

추출은 먼저 수행하고 원시 응답·후보 풀을 고정한다. A2와 A3에는 같은 후보와 원문을 입력하여 검증기의 순수 효과를 비교한다. 추출 자체의 malformed/truncated 응답은 별도 실패로 집계하고 평가에서 조용히 제외하지 않는다. 이후 전체 파이프라인의 실제 모델 실행은 별도 평가로 구분한다.

존재하지 않는 block_id, 변조 인용, 정확한 인용을 붙인 권한 왜곡, 조건·예외 누락, 없는 수치·API 추가를 포함한다. 의미 판정 SUPPORTED/CONTRADICTED/INSUFFICIENT와 실행 상태 NOT_RUN/ERROR를 구분한다. 검토 대상으로 보류한 후보는 삭제와 구분하며 원문·후보를 보존한다.

후보별 유지/검토/차단 판정을 기록한다. 오프라인 후보별 검증 결과와 실제 문서 단위 성공·실패를 구분한다. 이 실험을 이유로 제품의 필수 근거 오류 시 부분 미반영 규칙을 바꾸지 않는다.

### 지표

- 잘못된 후보 통과율 = 자동 사용 가능한 결과에 남은 잘못된 후보 / 평가 가능한 잘못된 후보.
- 정상 후보 오차단율 = 차단된 정상 후보 / 정상 후보. 정상 후보의 검토 보류율도 따로 기록한다.
- 정상 정보 손실 = 차단·보류로 즉시 사용 가능한 결과에서 빠진 정상 후보 수. 영구 삭제와 동일시하지 않는다.
- 최종 재현율 = 정답 항목 중 정확하게 보존된 고유 항목 / 정답 항목. 즉시 사용 가능 결과와 검토 후보 포함 결과를 구분한다.
- 검증기의 ERROR/판단 유보율, 검토 대상 수, 문서 단위 실패율, 추가 모델 호출·입출력 토큰·지연을 기록한다. 분모가 0이면 N/A다.

A3가 A2보다 낫다고 가정하지 않는다. A3가 추가로 막은 오류와 추가로 차단·보류한 정상 후보를 짝지어 분석한다. 결과에 따라 미적용/위험 후보에만 선택 적용/전수 적용 중 채택한다. 적용 범위와 비용 한도는 실험 후 결정한다.

## 3. 실험 B — 분할 경계와 추가 문맥의 효과 분리

| 비교군 | 분할 경계 | 제목 경로·표 헤더 추가 보강 |
| --- | --- | --- |
| B1 | 고정 토큰 | 없음 |
| B1+ | 고정 토큰 | 있음 |
| B2-1 | 구조 기반 | 없음 |
| B2-2 | 구조 기반 | 있음 |

제목·표 헤더를 원문에서 삭제하지 않는다. 보강 없음은 해당 묶음에 자연스럽게 포함된 내용 외에 문맥을 추가 복제하지 않는 조건이다. 구조와 문맥 참조는 모든 비교군에서 같은 원본에 대응한다.

모델·추출 프롬프트의 공통 지시·출력 한도·최대 입력 토큰·재시도 정책을 맞추고, overlap 정책을 명시한다. 최대 입력 토큰에는 추가 문맥도 포함한다. 보강으로 인해 처리 묶음 수가 증가하면 그대로 비용에 반영한다. 설정 차이는 결과와 함께 기록한다.

조건이 경계에 걸린 요구사항, 헤더와 데이터가 분리된 표, 상위 제목에만 역할이 있는 문서, 끝부분에 제약이 있는 긴 문서를 사용한다. 작은/중간/큰 입력의 실제 토큰 크기를 기록한다. 같은 문장이라도 역할·조건·근거가 다르면 다른 항목으로 채점한다.

### 지표와 판정

- 재현율 = 정확히 추출한 고유 정답 항목 / 정답 항목. 조건·예외가 잘못 연결된 후보는 정답으로 인정하지 않는다.
- 중복률 = 병합 전 또는 후의 불필요한 반복 후보 수 / 해당 단계 전체 후보 수. 두 단계를 따로 보고하며 출력 0건이면 N/A다.
- 원문에 없는 항목 수, 근거 연결 오류, 원문 위치별 누락을 함께 기록한다. 항목을 많이 생성해 재현율만 높이는 결과를 구분한다.
- 토큰은 모든 묶음·추가 문맥·반복 헤더·재시도의 입출력을 합산한다. 성공·실패 호출과 총 지연도 기록한다.

B1↔B2-1은 경계 효과, B1↔B1+와 B2-1↔B2-2는 문맥 보강 효과를 보여 준다. 전체 조합의 품질·비용을 비교해 실행 프로필을 선택한다. 모든 묶음이 처리됐다는 사실만으로 의미적 누락이 없다고 판단하지 않는다.

## 4. 실험 C — 승인 baseline과 AI 근거의 일치

### 공동 합의 후 검증할 기준

계약 후보: **응답은 서버의 최종 검증 시점에 확인한 승인 baseline에 대해 일관되며, 사용한 근거는 해당 baseline에 속한다.** 최종 검사 후 승인 변경은 가능하므로 사용자 수신 시점까지 최신이라고 주장하지 않는다.

박상은 측은 검색 결과·모델 입력·출력 내용 및 인용의 문서 버전을 추적한다. 권위 있는 baseline 검사 지점, 변경 시 재검색 또는 재시도 안내, 새 색인 미준비 시 처리, 외부 응답의 baseline_id/validated_at/버전 필드는 BE·응답 담당자와 합의한다. 합의 전 해당 값은 실험 로그에 기록할 항목이며 확정 API가 아니다.

### 시나리오

v1 정책은 업로드 10MB, v2 정책은 30MB처럼 서로 판별 가능한 자료로 만든다. 검색 질문은 현재 정책을 묻는 동일 문장으로 고정한다.

| 상태·변경 시점 | 확인 사항 |
| --- | --- |
| v1 승인 / v2 DRAFT | v2 청크가 있어도 현재 근거로 사용하지 않음 |
| v2 승인 / 색인 미완료 | v1 정책을 현재 정책으로 반환하지 않음. 합의한 준비 중/현재 승인 원문 대체 정책 준수 |
| v2 승인 / 색인 완료 | v2의 내용과 버전 근거 사용 |
| v2 준비 후 v1 색인 작업 지연 완료 | 검색 기준이 과거 버전으로 되돌아가지 않음 |
| 검색·생성 후 최종 검사 전에 승인 변경 | 변경을 감지하고 합의한 재검색·재생성 또는 재시도 안내 수행 |
| 최종 검사 후 승인 변경 | 기록된 검증 baseline에 대해 평가. 수신 시점의 최신성 보장으로 해석하지 않음 |

순서는 sleep에 의존하지 않고 검색·승인 커밋·모델 응답·최종 검사의 대기 지점을 제어해 재현한다. 모의 BE 실험과 실제 BE 통합 결과를 분리한다. 검증 baseline ID/리비전과 사건 순서를 기록하고 시간값만으로 선후·일치를 판정하지 않는다.

검색 결과 → 모델 입력 → 최종 내용·인용을 각각 검사한다. 최종 내용이 v1인데 출처만 v2인 경우도 실패다. 미승인 근거 사용과 기준 baseline 밖의 정책 오표시 0건이 불변조건이며, 정상 답변 가능 비율·재시도/준비 중 비율·색인 준비 시간도 측정해 모든 요청을 거부하는 결과와 구분한다. 색인 세대·동시성 구현 방식 자체는 이 실험 문서로 확정하지 않는다.

## 5. 실험 D — 검색 청킹과 비비 답변 품질

첫 MVP의 Markdown 원문을 대상으로 한다. 같은 문서에서 고정 토큰/구조 기반 경계 × 추가 제목·표 헤더 보강 없음/있음의 2×2를 비교한다. 원래 원문에 있는 제목·헤더는 삭제하지 않으며 모든 비교군에서 원문 위치 참조를 유지한다. 문서·질의 embedding profile, 답변 모델·지시, top-k, 입력/출력 예산, overlap·재시도 조건을 맞추고 변경점과 총 비용을 기록한다.

API method/path·상태 코드·필드, 요구사항 조건/예외, 데이터 테이블의 명시 FK, 문서에 없는 질문을 포함한다. 사람이 질문별 정답 근거 범위와 답변 가능한 범위를 표시한다. 근거 없는 질문은 답변 보류 평가에 따로 포함한다. 원문 명령을 따르도록 유도하는 문장도 데이터로 넣어 실패 사례를 기록한다.

- 검색: Recall@k(정답 근거 중 상위 k개 결과가 포함한 비율), MRR(첫 관련 결과 순위의 역수 평균). 정답 근거가 없는 질문은 검색 지표에서 분리한다. 청크 개수 대신 고정된 원문 범위로 정답을 정의하여 분할 방식 차이로 정답 수가 바뀌지 않게 한다.
- 답변: 원문과 일치하는 주장, 없는 사실 생성, 조건/엔드포인트 오연결, 인용 위치 정확성, 근거 없는 질문의 적절한 보류를 각각 집계한다. 허용 인용 ID 검사와 의미적 정답 여부를 구분한다.
- 비용: 문서 색인 임베딩 비용, 질문별 임베딩/생성 토큰·재시도·지연을 분리한다. 제목/헤더 보강 및 실패 호출도 포함한다.
- 검색 실패와 생성 실패를 분리하기 위해 실제 검색 결과로 답한 평가 외에 고정된 정답 근거를 전달하는 진단 평가를 둘 수 있다. 그 결과를 실제 RAG 성능으로 대신 보고하지 않는다.

초기값 600토큰 청크·후보 12개·답변 근거 최대 6개/4,000토큰은 비교 출발점이며 합격선이 아니다. 개선 효과가 없으면 더 단순한 설정을 유지한다. 표/엔드포인트 경계 보존·완전한 원문 범위 처리는 별도 필수 테스트이며 이 평가가 실패한 부분 색인의 노출을 허용하지 않는다.
