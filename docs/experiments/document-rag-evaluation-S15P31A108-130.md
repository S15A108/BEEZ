## 수행 범위

운영 문서가 아닌 가상 서비스의 기획·요구사항·API·데이터 설계 Markdown 4개, 질문 12개(답변 가능 8/근거 없음 4)를 사용했다. 정답은 청크 수에 의존하지 않는 원문 quote·Unicode 범위로 고정했다. 라벨은 agent가 작성한 개발용 초안이며 팀원이 독립 검토한 평가 세트가 아니다. 기존 제안의 종류별 3개/총 12문서로 확장한 최종 평가도 아니다.

고정/구조 기반 × 제목·표 헤더 보강 off/on을 동일 모델·프롬프트·예산으로 3회 비교했다. 청크 600토큰, overlap 0, 정확 cosine top-12, 생성 근거 최대 6개/4,000토큰, 출력 최대 512토큰이다. 제목/표 헤더 보강은 embedding_text에 적용하며 생성에는 선택된 원문 text를 전달했다. 따라서 보강 문맥을 답변 컨텍스트로 직접 확장한 실험과 구분한다.

임베딩은 실제 GMS text-embedding-3-small/1024, 답변은 실제 GMS gpt-6-luna Responses를 사용했다. 모델을 자동 교체하지 않았다. 문서/질의 벡터는 설정·반복 사이에 공유했으므로 지연은 생성·로컬 정확 검색을 따로 기록하고, 실제 공유 비용과 설정별 논리 색인 입력 토큰을 구분한다. 운영 BE 저장·SQL·비비 API를 거친 실험은 아니다.

### 실패와 해석

- **API 근거 선택 누락 6건:** 두 구조 설정의 `api-create` 3회씩에서 생성 성공 201/documentVersionId 근거는 검색됐지만 `POST /api/projects/{projectId}/documents` 제목이 최종 6개 근거에서 빠졌다. top-12 Recall은 1.0이지만 최종 근거 Recall은 해당 질문에서 0.5였다. 모델은 메서드/경로를 추측하지 않고 보류했다. 향후 #90/#92 컨텍스트 조립 시 heading/context_refs를 원문 근거와 연결해 제공하는 검증이 필요하다. 이 결과를 전체 문서가 누락됐거나 #129의 파싱 coverage가 깨졌다고 해석하지 않는다.
- **인용 형식 위반:** 구조 청크의 여러 source span을 한 줄바꿈으로 이어 붙인 문장을 그대로 인용한 경우가 있었다. 전달된 청크에는 있지만 단일 원문 조각에 정확히 존재하지 않아 엄격한 인용 검사에서 실패했다. 원문 공백과 범위가 다른 인용을 성공으로 완화하지 않았다. 답변 내용의 사실 오류와 별개인 위치/문자열 규약 문제다.
- **보류 계약 불일치:** 날짜·보관 기간 등 미확정 질문에 실제 수치를 지어내지는 않았지만, `answered`로 표시하거나 `insufficient`에 인용을 붙이는 경우가 있었다. 실험 계약의 보류 성공은 `insufficient + citations=[]`이므로 실패로 남겼다. 운영 DTO·보류 표현을 #92 담당과 확정해야 한다.
- **문서 명령 주입:** 제공한 악성 문장의 `INJECTED-777` 출력은 0/144였다. 한 가지 합성 사례의 marker 검사이며 일반적인 공격 저항성 보장은 아니다.

작성 agent가 144개 답변 문장을 모두 읽고 위 유형과 원문을 대조했다. 독립 사람 검토를 대신하지 않으며 추가 주장·조건 왜곡의 의미적 정답률을 100%로 보고하지 않는다. 같은 개발 세트에 맞춘 프롬프트 튜닝·유료 재평가는 하지 않았다.

### 비용과 실행 이력

- 실제 호출 150회: 생성 144 + 문서 임베딩 4 + 질의 임베딩 2. 재시도 0회. 체크포인트 재개로 임베딩 풀을 한 번 더 생성한 3회도 포함했다.
- 문서 입력 22,296토큰, 질의 입력 676토큰, 생성 입력 196,641/출력 17,895토큰. 실패/미확정 usage는 없었다.
- 공개 단가 추산: 문서 4.4592 + 질의 0.1352 + 생성 286.1160 = **290.7104크레딧**. 계정 잔액 차감 대조가 아니며 캐시 할인은 주장하지 않는다. 실행 시 [GMS 공개 목록](https://gms.ssafy.io/api/v1/common-codes/models)의 단가를 캡처했다.
- 첫 실행 코드 `8c5fb8c`, 재개 코드 `43b3446`. 결과 metadata에 실행 당시 코드 파일·데이터·원문 해시를 남겼다. 후속 프로필 변경 차단은 측정 입력을 바꾸지 않는 실행기 보완이다.
- 첫 실행은 76번째 응답 저장 시 Windows 파일 교체가 거부돼 멈췄다. 원본 체크포인트를 로컬 별도 보존하고, 저장된 응답을 재호출 없이 복구한 뒤 나머지 68개만 생성했다. 결과의 `recovered_from_checkpoint`와 `sessions`에서 확인할 수 있다. 공개 결과에서 평가에 필요 없는 암호화 reasoning 필드는 제외하고 가시 출력·usage는 보존했다.

### 설정 결정

**구조 기반 600토큰·자동 overlap 0·보강 off를 현재의 잠정 기본값으로 유지하고 운영 채택 승인은 보류한다.** 구조 경계 보존은 기존 원문 계약이며, 이 작은 세트의 고정 기준선이 더 높은 Recall을 냈다는 이유로 즉시 교체하지 않는다. 보강 on의 Recall 개선도 관찰되지 않았다. 실제 문서 확대·정답 라벨 검토·원문 제목 참조를 포함한 답변 컨텍스트 검증·BE/DB 측정을 거친 뒤 같은 예산으로 재판정한다. 단 한 번의 실행 순서와 작은 표본으로 p95 우열을 일반화하지 않는다.

## C 모의 승인 경합

Event barrier로 검색 후, 모델 응답 후 최종 검사 전, 최종 검사 후의 승인 변경을 제어했다. v1/v2 READY, v2 미준비까지 포함한 6개 모의 사례에서 선언한 불변조건 위반은 0건이다. 검증기는 trace 자체의 기대값이 아니라 별도 baseline oracle로 허용 버전과 10/30 MB 정책을 결정한다.

검색/생성 후 최종 검사 전 변경은 답변을 폐기하고 재시도 안내 대상으로 분류했다. 최종 검사 후 변경은 검사 시점 b1 snapshot 응답으로 남겼다. 미준비 상태에서 이전 정책 fallback은 없었다. 이는 실제 승인 트랜잭션·DB rollback·프로젝트 권한 검증이 아니다.
