## 개요

AI 색인 산출물을 기존 BE 저장·검색 구현과 대조할 수 있도록 검증 데이터와 실행 도구를 제공하고, Markdown 검색 방식별 실제 GMS 개발용 측정 결과를 기록합니다. #130은 AI 도구·평가·인계까지로 종료하며, 이미 구현 중인 오서현 담당 BE 작업을 새로 배정하지 않습니다. 실제 HTTP 계약과 DB 통합 검증 완료는 구분합니다.

## 작업 내용

- 실제 파서·청커·PreparedIndex 형식의 합성 packet과 검색/발행 검증 시나리오 26개를 제공합니다.
- 독립 baseline oracle과 Event barrier를 사용하는 승인 경합 모의 검증 6개를 구현했습니다.
- 합성 Markdown 4종·질문 12개를 고정/구조 청킹 × 문맥 보강 off/on으로 3회 비교했습니다. 실제 GMS 답변 144개, 물리 호출 150회, 공개 단가 추산 290.7104크레딧입니다.
- 원문 범위 기반 Recall/MRR, 인용·보류 검사, 실제 usage·지연·실패·코드/데이터 해시와 재생성 가능한 요약을 보존했습니다.
- 호출/비용 제한, 미확정 usage 보존, 비정상 출력 처리, 중단 체크포인트 복구와 프로필 변경 차단을 구현했습니다.

## 변경 사항·검증

- 기존 운영 라우터·공유 API·DB migration은 변경하지 않습니다. 선행 AI 모듈은 PR #21에서 제공합니다.
- 전체 AI 테스트 175개·Ruff 통과. Windows의 기존 Proactor socketpair 초기화 오류를 구분하기 위해 최종 전체 검증은 테스트 프로세스에만 Selector/session 정책을 적용했습니다. Linux CI·운영 설정은 유지합니다.
- 독립 코드 리뷰에서 발견한 응답 envelope 처리와 baseline 검증 문제는 회귀 테스트로 수정했습니다.
- 구조 설정의 API 제목 누락, source span을 건너뛴 인용 및 보류 상태/인용 규약 불일치를 기록했습니다. 합성 개발 자료의 결과이며 운영 품질·실제 DB 안전성을 보장하지 않습니다. 기본 설정은 잠정 유지합니다.

## 기존 BE 구현과의 연계 확인

BE 담당은 오서현입니다. `feature/backend-document-upload-S15P31A108-192`의 `f3362fe`에서 `DocumentIndexWorker`, V3 `document_processing`/`document_index_manifest`, 청크·벡터 저장·SQL 검색을 확인했습니다. 해당 브랜치 `docs/design/03-erd.md:56`에도 담당이 명시돼 있습니다. 기존 BE 티켓의 담당·범위·상태·이슈 연결은 변경하지 않습니다. 아래 내용은 기존 구현과의 대조 사항이며 #130 종료 선행 조건이 아닙니다.

| 대조 항목 | 입력·검증 기준 |
| --- | --- |
| AI DTO·프로필 소비 | `docs/design/document-chunking-search-contract-S15P31A108-129.md`. source span은 정규화 원문의 Unicode offset이며 key/hash/profile을 보존합니다. `PreparedIndex`는 READY 발행 증거가 아닙니다. |
| 실행·상태·저장 구조 | `docs/design/document-index-refresh-contract-S15P31A108-130.md`의 요구사항과 기존 worker/V3 migration의 run/attempt/lease·SOURCE/INDEX·manifest를 대조합니다. 새로 개발할 미할당 작업이라고 해석하지 않습니다. |
| 원자적 발행·복구 | 기존 코드에 청크 전량과 manifest를 교체하는 트랜잭션이 있습니다. packet의 부분 배치·오래된 실행·중복·rollback 사례로 실제 동작과 기존 READY 보존을 검증할 수 있습니다. |
| 범위 제한 SQL 검색 | 기존 코드에 baseline·project·profile 제한 및 cosine 정렬이 있습니다. 허용 버전·READY·권한·미준비/fallback 계약의 실제 충족 여부를 fixture와 대조합니다. |
| 호출 예산 | AI 전체 90초·공급자 호출별20초와 BE 기본 read timeout20초 차이를 처리합니다. 전용 timeout 또는 작업 접수 방식을 선택하고 실패/취소/usage를 기록합니다. |

| 운영 비비 연결 | heading/context_refs·원문 위치를 누락하지 않고 전달하며 인용/보류 응답을 매핑합니다. 새 AI 컨텍스트·프롬프트 구현이 필요하면 관련 #90/#92 등 별도 AI 티켓으로 추적합니다. |

### 현재 확인된 HTTP 계약 차이

- **청킹 경로:** BE `AiClient`는 `POST /v1/document-chunks`를 호출하지만 현재 AI 앱에는 해당 라우터가 없습니다. 내부 `build_chunks`/`PreparedIndex`를 공개 HTTP 응답으로 간주하면 안 됩니다.
- **청킹 입력:** BE는 `normalization_profile=utf8-lf-v1`, `chunking_profile_id=md-structure-v1`을 보냅니다. AI 제안은 `normalization_version`/`parser_profile`, `structure-v1`입니다. 동일한 이름으로 임의 간주하지 않습니다.
- **청킹 출력:** BE는 result의 버전/request_key/text_hash/chunking_profile_id 및 청크별 행 locator를 검사합니다. AI 내부 형식은 manifest·source_spans·context_refs·embedding_text입니다. 긴 행 하위 분할과 반복 문맥을 포함해 명시적 매핑이 필요합니다.
- **임베딩:** BE는 `embedding_profile_id`와 `purpose=DOCUMENT|QUERY`를 보내고 result에도 두 필드를 기대합니다. 현재 AI-A04는 추가 요청 필드를 거부하며 result는 model/dimension/vectors만 제공합니다. 단순 호출 연결만으로 호환되지 않습니다.

위 차이는 코드/스키마 대조로 확인했으며 이번 평가 PR에서 공통 API나 상대 브랜치를 변경하지 않습니다. 필요한 청킹·임베딩 HTTP 연계 보완은 해당 구현 범위에서 처리하고, #130은 차이·인계 자료·검증 결과를 남기는 범위로 종료합니다.

`ai/`에서 실행할 수 있습니다. packet 생성·기본 평가는 모델을 호출하지 않습니다. `--live`는 비용이 드는 명시적 실행입니다.

```text
python -m scripts.prepare_tokenizer
python -m scripts.generate_retrieval_handoff --output <경로>/handoff.json
python -m evaluations.document_rag --output <새 경로>/dry.json
python -m evaluations.summarize <기존 실측 JSON> --output <경로>/summary.md
```

상세 인계: `ai/evaluations/README.md`, `docs/experiments/document-rag-evaluation-S15P31A108-130.md`. 측정 자료: `docs/experiments/results/S15P31A108-130-rag-dev-v1.json` 및 `-summary.md`. 정답 라벨/운영 자료 검토와 운영 채택 기준은 이후 통합 검증 사항입니다.
