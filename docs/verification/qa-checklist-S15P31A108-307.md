# 서비스 QA 체크리스트

Jira: S15P31A108-307 · 기준: dev `0580368f` · 작성일: 2026-11-09

프로젝트·문서·작업 검증·회의·AI·발행 후 동기화의 주요 정상 및 예외 흐름을 확인한다. 이 문서는 **실행 계획**이며 아래 항목은 모두 미실행이다. 자동 테스트 코드와 설계 문서는 기대 동작의 근거이지, 이번 QA의 실행 결과가 아니다.

## 실행 준비와 기록

- 환경: 팀이 정한 격리된 테스트 환경을 사용한다. 실행 시 배포 주소, FE/BE/AI 버전과 커밋, DB·검색 연결, 실행 일시와 담당자를 아래 기록표에 기입한다. UI가 없거나 연결되지 않은 경로는 해당 API/MCP로 확인하고 경로를 기록한다. 화면과 API의 확인 결과는 구분한다.
- 계정·데이터: 프로젝트 A의 사람 팀장 L, 서로 다른 팀원 M1·M2, 프로젝트 B의 팀원 X와 비로그인 세션을 준비한다. A에 작업과 문서, 승인·발행 가능한 기준 버전 및 M1 에이전트 토큰을 준비한다. 데이터 생성·외부 서비스 장애 주입 및 CDC 재수신은 공유 환경에 영향을 주므로 격리 환경에서 담당자와 조율한다. 케이스에서 별도 조건을 지정하면 그 조건을 우선한다.
- 결과: 실제 결과는 `미실행`, `통과`, `실패`, `차단(사유)` 중 하나와 관찰한 상태·시간·응답 또는 화면 증거 링크로 바꾼다. 결함 칸에는 이슈 링크와 재현 조건을 기록하고, 결함이 없으면 `없음`으로 기입한다. 실제 서비스의 개인정보·토큰·원문은 증거에서 제거한다.
- 우선순위: P0은 권한·데이터 무결성·작업 시작/발행에 영향을 주는 항목, P1은 주요 흐름, P2는 보조 흐름이다. 범위나 환경이 준비되지 않으면 통과로 간주하지 말고 차단 사유를 남긴다.

## 확인이 필요한 범위와 후속 작업

- 결과 재사용 캐시와 무효화 정책은 별도 협의 대상이다. 현재 검증 재시도·멱등 재전송과 일반 결과 캐시를 동일한 기능으로 취급하지 않는다.
- Q-01~03의 질문 API와 화면 연동, 실제 검색·모델 접근은 실행 전 확인이 필요하다. 외부 AI 응답의 품질은 동일 입력이라도 달라질 수 있으므로 응답·근거·모델 및 시각을 함께 보존한다.
- CDC에서 실패·미평가 항목의 사용자 재처리 API와 운영 절차는 미확정이다. Kafka/Connect·복구 스캔 활성화 여부, 격리 장애 시험 승인과 운영 담당자를 확인해야 한다. 최초 v1과 도입 전 백필은 자동 분석 대상이 아니다.
- 이 체크리스트가 전 항목 실행·통과 또는 실제 운영 연동의 완료를 의미하지 않는다. 차단과 범위 차이는 원인과 담당자를 남기고 별도 후속 작업으로 추적한다.
