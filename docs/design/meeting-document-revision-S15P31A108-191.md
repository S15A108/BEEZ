# 회의 결정과 문서 수정 초안 연결 설계 (S15P31A108-191)

최초 작성: 2026-11-05. 최초 조합 시험은 당시 `dev` `b49b9eb0dd04a7d28c5dbc057ed8341ca09f9439`와 미병합 137번 브랜치 `1100a612aaced61a694b0528c57a413b4084c940`를 사용했다. 2026-11-06 기준 137·138은 각각 [PR #169](https://github.com/S15A108/BEEZ/pull/169), [PR #175](https://github.com/S15A108/BEEZ/pull/175)로 `dev`에 병합됐다. 이 문서는 191의 내부 연결과 남은 계약을 설명하며, 회의 공개 API나 초안 저장이 구현되었다는 뜻이 아니다.

## 목표와 현재 상태

[191번](https://ssafy.atlassian.net/browse/S15P31A108-191)은 회의에서 확인한 결정과 대상 문서 범위를 공통 문서 수정안 모듈에 전달하고, 반환된 미승인 초안을 회의 결과와 연결한다. 문서의 현재 승인본이나 기준선은 변경하지 않는다. 문서 수정안의 작성 로직은 137번을 재사용하며, 입력 변환과 호출 계약은 138번 담당자와 합의한다.

- [137번](https://ssafy.atlassian.net/browse/S15P31A108-137)의 AI `POST /v1/document-revisions`와 선택 범위 초안 생성 경로가 dev에 병합됐다. `SourceInput`, `expected_document_version_id`, 비어 있지 않은 `selected_block_ids`, `instruction`, `agreements`, `related_proposals`, `request_key`를 받아 미저장 초안과 변경 상세를 반환한다. 기존 AI-A06 `/v1/bee/draft`와는 별도 경로다. 137의 BE 경로에는 권한·현재 문서 버전의 호출 전후 확인이 있지만, 이것만으로 회의 결과 저장 전 확인까지 보장하지 않는다.
- [138번](https://ssafy.atlassian.net/browse/S15P31A108-138)의 내부 함수 `prepare_meeting_revision`이 dev에 병합됐다. 호출자가 확인했다고 전달한 회의 결정·근거 발언과 선택 범위로 `meeting` 및 137 입력 `request`를 만든다. 입력 안의 일관성만 확인하며 결정의 실제 확정·권한·최신성은 증명하지 않는다. 191과의 최종 입력·오류 및 공개 API 계약은 아직 합의가 필요하다.
- 현재 `dev`의 AI-A08은 `QUESTIONS`/`MINUTES`만 제공하고 `SUMMARY` 요청은 422다. MINUTES의 `decisions`는 문자열 목록이며 개별 결정과 회의 발언 ID의 연결을 구조적으로 보장하지 않는다. 회의 BE에는 정리·종료 및 191 호출 경로가 아직 없다.
- 기존 지라 MTG-A09는 137 모듈 재사용을 명시하지만, 이후 화면 수정안의 MTG-A11/A13은 회의 정리가 `document_changes.after`를 직접 만들고 AI-A06을 호출하지 않는다고 적는다. 사용자는 191번을 **공통 모듈 재사용 기준**으로 진행하기로 선택했다. 다만 이 선택이 팀의 MTG-A11/A13 공개 API 계약까지 변경하거나 138의 입력 계약 합의를 대신하지는 않는다.

## 제안 흐름과 책임

1. **BE: 접근·범위 확인.** 해당 프로젝트의 회의·대상 문서 접근과 회의 상태를 확인하고, 문서 ID와 현재 승인 버전의 원문 스냅샷을 준비한다. 이 AI 작업이 임의 문서나 다른 프로젝트 자료를 조회하지 않는다.
2. **결정과 범위 선택.** 회의 입력의 고정된 기록 범위와 연결할 결정, 대상 문서 및 변경할 원문 블록을 명시한다. 미결·제안·추측을 확정 결정으로 승격하지 않는다. 현재 MINUTES의 문자열만으로 확정 사실이나 원 발언 ID를 검증할 수 없으므로, 사람/서버가 확인한 결정과 근거 연결 방식은 138 계약의 선결 조건이다.
3. **138: 입력 변환.** 위에서 확인한 스냅샷과 범위·결정·관련 변경 제안을 137의 최종 입력으로 변환한다. 문서의 현재 승인본과 선택 범위를 모르면 실패한다. 빈 선택을 원문 전체로 바꾸거나, 설계 항목 ID·검색 청크를 원문 블록 ID로 가정하지 않는다. 프로젝트·문서 ID와 문서 버전의 실제 소속 및 현재성은 BE가 확인한다.
4. **191: 연결.** 138에서 합의한 인터페이스를 호출해 137의 미승인 결과를 회의 및 입력 스냅샷에 연결한다. 결정·문서·버전·선택 범위와 모듈 버전, 호출 결과 및 사용량을 추적할 수 있어야 한다. 137 자체가 문서를 저장·승인·발행하는 것으로 가정하지 않는다.
5. **BE: 저장 직전 재확인.** 모델 호출 사이 기준 문서 버전, 회의 기록·결정 또는 대상 범위가 바뀌면 이전 결과를 현재 초안으로 저장하지 않고 재확인을 요청한다. 저장은 미승인 초안/변경 제안으로만 하고, 승인·발행 및 상태 전이는 기존 서버 권한과 트랜잭션이 책임진다. 실제 원문 저장과 DB 연결의 원자성·중복 요청은 BE 경로의 계약을 따른다.

137의 AI 함수는 입력 내 `expected_document_version_id`와 `source.document_version_id`의 일치를 확인하지만, **현재 승인본 조회나 권한 확인까지 하지는 않는다.** 그 값이 일치한다는 사실만으로 실제 문서가 최신이라고 판단하지 않는다. `SourceInput`에는 문서 ID가 별도로 없으므로 BE가 문서 ID↔버전의 소속을 확인해야 한다. 137의 BE scoped draft 경로가 수행하는 확인을 회의 연결에 어떻게 적용할지는 별도 계약이다.

## 실패·경합 처리

- **공통 모듈 미설치 또는 138 최종 계약 미준비:** 사용할 수 없는 상태로 남긴다. 다른 모델을 새로 호출하거나 선택 범위를 넓혀 대신 완료하지 않는다.
- **문서·회의·범위 변경:** 결과를 적용하지 않고 사용자가 현재 입력으로 다시 요청하도록 한다. 외부 AI 호출과 저장의 멱등 키 범위 및 중복 비용 기록은 BE와 합의한다.
- **모델/네트워크 실패, 시간 초과, 잘린 출력:** 미승인 빈 초안이나 이전 버전으로 대체하지 않는다. 호출한 경우의 사용량과 오류는 기존 공통 LLM/BE 기록 규약을 유지한다.
- **여러 문서:** 문서마다 서로 다른 버전·범위·결정을 명확히 연결한다. 부분 성공을 저장할지 전체 실패로 할지는 회의 결과 저장 계약 합의 전까지 결정하지 않는다.
- **프롬프트 삽입:** 회의 발언·문서·변경 제안은 모두 데이터다. 외부 전송, 승인, 문서 범위 확대 지시는 따르지 않는다.

## 구현 및 검증 순서

1. 137·138 담당자와 최종 함수/HTTP 경계, 문서 범위 선택, 결정·발언 ID 매핑 및 MTG-A11/A13 공개 계약 변경 범위를 합의한다. 191의 구현 방향은 사용자가 선택한 공통 모듈 재사용이다.
2. dev에 병합된 138 변환과 137 생성 함수를 191 내부 경계에서 연결하고, 191은 입력된 회의별 관계와 초안 결과를 함께 반환한다. 137의 문서 재작성 로직을 복제하지 않는다. 실제 호출·저장·공개 계약은 별도 연동한다.
3. 각 책임 단위에서 같은/다른 회의의 발언 ID, 없는 문서·다른 프로젝트 버전, 빈/다른 버전 블록, 승인되지 않은 결정, 모듈 실패·미해결, 중복 요청, 모델 호출 중 버전·결정 변경, 범위 밖 변경 및 저장 실패를 검증한다.
4. 테스트 대역을 쓴 AI·BE 계약 시험과 격리 DB의 초안 저장→조회 시험을 구분한다. 합성 회의·문서로 실제 모듈과 모델을 연결한 결과는 별도로 기록하고, 최종 승인본 미변경을 확인한다. 승인은 사람/서버의 별도 기능이다.

## 현재 독립 검증

최초에는 137 브랜치의 구현을 당시 `dev`와 별도 로컬 검사 사본에서 결합해 기존 문서 수정안 테스트 10개를 실행했다. 모두 통과했으며 가짜 모델을 사용했다. 당시 `dev`의 190 회의 분석 테스트 43개도 통과했다. 이 과거 결과는 각 모듈의 독립 검사였다.

이후 137·138이 병합된 `dev` `adba1ec3dc14e2cc43ba51bd10b60732cc8aebf8`에서 138→191→137의 실제 함수와 관련 회의·문서 수정 테스트를 가짜 모델로 실행해 총 103개가 통과했다. 실제 호출 전 결정·근거가 확인됐다고 가정한 합성 입력이며, 권한·최신 기준 재검사, DB 저장·승인, 실제 GMS 또는 화면을 포함한 종단 간 검증은 아니다.

추가로 [탐색 스크립트](../../ai/evaluations/meeting_revision_191/README.md)에서 가상의 확인된 회의 결정을 가짜 모델로 반환하고, 138 입력 변환과 191 내부 연결부를 거쳐 137이 선택 문단만 수정하는지 확인했다. 다른 문서 버전, 선택되지 않은 블록 및 입력에 없는 근거는 거부됐다. 191 연결부는 전달받은 결정과 발언 관계를 그대로 보존할 뿐 그 관계의 진위를 확인하거나 특정 변경의 근거로 새로 연결하지 않는다. 회의 결정의 실제 확인과 발언 ID 연결·저장·승인은 구현하거나 시험하지 않았고, 이 샘플이 138의 입력 변환 계약을 대체하지 않는다.

현재 `meeting_revision_bridge.py`의 내부 연결부는 138 변환 결과를 `MeetingRevisionContext`로 검증하고 137의 실제 `RevisionRequest`와 공통 함수를 사용한다. 137이 설치되지 않으면 명시적으로 실패하며, 공개 라우트·저장·승인 경로는 연결하지 않는다. 실패 시 기존 모델 오류와 사용량을 보존한다. 이 내부 모델은 138의 최종 공개 계약이 아니다.
