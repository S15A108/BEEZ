# 회의 결정 기반 문서 수정 초안 (S15P31A108-191)

회의에서 사용자가 확인한 결정과 근거 발언을 현재 승인 문서의 선택 범위에 연결해 미제출 수정 초안을 만든다. 138의 `prepare_meeting_revision`으로 입력을 검증하고 137의 문서 수정 생성기를 재사용한다. 초안 생성은 문서 승인·발행이나 변경 제안 제출을 수행하지 않는다.

## 사용 흐름

1. 회의 정리를 생성하거나 최신 정리를 불러온다. AI가 만든 결정은 사실 확정을 보장하지 않는다.
2. 사용자가 반영할 결정과 결정별 근거 발언, 대상 승인 문서와 수정할 블록을 고르고 확인한다. 결정에 연결된 발언은 사용자가 확인한 관계이며 AI가 원인 관계를 입증한 것이 아니다.
3. 서버가 참여·권한, 최신 회의 정리와 회의 기록 범위, 실제 회의의 텍스트 발언, 현재 승인 문서 버전과 선택 블록을 검증한다.
4. 내부 AI `POST /v1/meeting-revisions`가 138 입력 변환 → 191 브리지 → 137 생성기를 호출한다. 선택 범위 밖의 변경이나 출처 불일치는 거부한다.
5. 모델 호출 뒤 서버가 회의·정리·문서 버전과 권한을 재확인하고 별도 `meeting_revision_draft`에 미제출 초안을 저장한다. 기존 변경 제안 생성 API는 제출 알림을 보내므로 여기서 호출하지 않는다.
6. 사용자는 저장된 전체 초안을 확인·복사한 뒤 해당 문서의 변경 제안 화면에서 직접 붙여 넣고 제출할 수 있다. 이 수동 흐름은 회의 출처를 변경 제안에 자동 연결하지 않는다.

## 계약과 제약

- `POST /api/projects/{projectId}/meetings/{meetingId}/revision-drafts`: `Idempotency-Key`와 `summary_id`, `document_id`, `base_document_version_id`, `selected_block_ids`, `instruction`, `decisions`, `confirmed`가 필요하다. `decisions`는 정리의 0부터 시작하는 `decision_index`와 사용자가 지정한 `evidence_entry_ids` 목록이다. 결정 문구는 서버가 정리에서 가져온다.
- `GET .../revision-drafts/latest`와 `GET .../revision-drafts/{draftId}`는 저장한 초안을 조회한다. 회의 정리·기록 조회와 같이 프로젝트 멤버 접근을 따른다.
- 같은 회의의 정리 시점까지 존재한 텍스트 발언만 근거로 선택할 수 있다. 정리의 `through_entry_id`가 그 범위의 모든 발언을 모델이 실제로 봤다는 증거는 아니다. 정리에 쓰인 입력은 길이 제한으로 일부만 포함될 수 있다.
- 문서 버전이 바뀌거나 새 회의 기록 또는 새 정리가 생기면 결과를 저장하지 않고 다시 확인하게 한다. 한 번의 초안은 하나의 문서와 명시적으로 선택한 블록만 다룬다.
- 생성 시 팀장이자 회의 참여자인 사람이 명시적으로 확인해야 한다. 생성과 저장은 중복 요청 키와 입력을 확인하며, 새 초안은 승인본을 수정하지 않는다.
- 137이 반환하는 변경 근거는 회의 결정 텍스트의 인용이다. 결정별 발언 ID는 별도 회의 맥락으로 보존하며 개별 변경의 직접적인 발언 근거로 자동 연결하지 않는다.
- MTG-A11의 `SUMMARY` 응답에는 문서 변경 제안이 포함될 수 있지만, 191 초안은 그 문안을 그대로 저장하지 않고 사용자가 확인한 결정을 공통 문서 수정 모듈에 전달해 생성한다. 회의 종료 및 별도 변경 제안 제출·승인 과정은 이 경로의 책임이 아니다.

## 검증 범위

AI 단위·계약 테스트는 138→191→137의 실제 함수 조합과 내부 인증, 잘못된 발언 참조 및 선택 범위를 검사한다. BE 테스트는 권한·최신성·저장·중복 요청과 AI 응답을 확인하고, 프론트 테스트는 사용자의 결정·근거·문서 범위 선택을 확인한다. 실제 GMS에 가상 결정 세 건을 전달하는 별도 스모크 테스트는 [실행 방법과 한계](../../ai/evaluations/meeting_revision_191/README.md)를 따른다. 스모크 테스트 결과를 실제 회의 전반의 정확도나 사용자 승인 검증으로 해석하지 않는다.
