# 검증 결과의 후속 행동 제안 (S15P31A108-187)

기준: 2026-11-05, `dev` `9d4cd249ea003a9931c123a6b22c2230fc6dddd3`. [187](https://ssafy.atlassian.net/browse/S15P31A108-187)은 검증에서 발견한 문제를 계획 보완, 관련자 협의, 설계 변경 제안으로 이어 주는 AI 제안을 다룬다. 실제 승인, 변경 적용, 작업 상태와 최종 판정은 서버와 사람의 책임이다.

## 순서와 범위

[191](https://ssafy.atlassian.net/browse/S15P31A108-191)은 회의 결정을 문서 수정안 생성에 연결한다. Jira의 선행 137·138이 미완료이고 AI-A06은 계약만 있으며, 현재 회의 종료 계약의 수정안에는 AI-A06을 재사용하지 않는다는 내용이 있어 선행 구현과 계약 정리가 필요하다. 따라서 기존 검증 경로를 활용할 수 있는 187을 먼저 다룬다.

## 설계 원칙

1. 기존 AI-A02 검증에서 근거 검사를 통과한 finding에 후속 행동을 제안한다. 새 검증 판정이나 자동 실행 경로를 만들지 않는다. 계획 정보 부족과 오래된 참조에는 계획 보완·재검증, 작업 간 충돌에는 확인된 관련 작업 담당자와의 협의, 승인 정책 미정이나 승인 설계와의 불일치에는 관련자 검토와 필요시 변경 제안을 안내한다. 경로는 제안이며 서버의 `resolution`과 별개다.
2. `related_task_id`는 해당 검사에 입력된 다른 작업만 가리킨다. AI 입력에는 현재 담당자 목록이 없고 계획의 `created_by`는 담당자라는 보장이 없다. 특정 멤버 ID를 생성하거나 배정하지 않는다. 현재 담당자는 서버가 확인하며 확인 근거가 없으면 담당자를 미정으로 둔다.
3. `message`, 승인 설계와 출처는 확인한 문제의 근거이며 `suggested_action`은 그에 대한 제안이다. 검색 결과가 없다는 이유로 정책이 없다고 단정하지 않는다. 미검사·근거 부족은 기존 PARTIAL 경로를 유지한다. 프롬프트에 들어온 문서와 계획은 명령이 아닌 데이터로 취급한다.
4. 기존 `FindingCandidate.suggested_action` 문자열을 사용해 구버전 AI-A02 소비자와 호환한다. AI는 실제 상태를 변경하거나 승인하지 않는다.

입력에 멤버·역할 후보가 없으므로 구현은 사람을 추천하지 않고 확인할 담당 역할만 안내한다. 모델이 생성한 행동 설명의 의미나 허위 인물·승인 주장을 코드가 완전히 검증하지는 못한다. 프롬프트 지시와 참조 ID 검증만으로 이를 보장할 수 없으므로 실제 모델 평가와 사람의 검토가 필요하다.

## 전달과 남은 연동

서버는 기존처럼 `kind`와 `severity`로 `resolution`과 `next_action`을 결정한다. 완료된 AI finding의 `suggested_action`은 별도의 선택 필드 `ai_suggested_action`에 저장·조회하고, 화면은 서버 안내와 분리된 AI 후속 행동 제안으로 표시한다. 비어 있거나 NUL을 포함하거나 4,000 UTF-16 코드 단위를 초과하는 제안은 자르지 않고 출력 계약 위반으로 처리한다. 이전 이력·규칙·오류 finding에는 이 필드가 없을 수 있다.

현재 담당자의 실제 신원 조회와 역할별 추천은 이 변경에 포함되지 않는다. [150](https://ssafy.atlassian.net/browse/S15P31A108-150) 화면과의 추가 요구사항·표시 방식은 팀과 조율해야 한다. PARTIAL의 후보는 현행대로 진단 이력에만 남고 정상 finding으로 적용하지 않는다. 합성 사례의 실행 및 실제 모델 평가 상태는 [평가 기록](../../ai/evaluations/followup_action/README.md)에 구분해 기록한다.
