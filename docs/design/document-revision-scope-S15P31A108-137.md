# 문서 수정 범위와 연계 검토 (S15P31A108-137)

## 기존 구조 확인

AI 원문 파서의 `SourceBlock.block_id`는 프로젝트, 문서 버전, 정규화 원문 해시,
파서 프로필·버전과 블록의 종류·행 범위에서 만들어진다. 같은 버전의 파싱 결과를
재사용해 문단, 목록 항목 등 선택 범위를 가리킬 수 있다. 버전이나 원문·파서가
달라지면 이전 ID가 유효하다고 가정하지 않는다. 공백과 파서가 제외한 범위는
선택할 수 없다.

BE의 설계 항목에도 ID와 `source_locator`가 있지만, 문서의 항목과 일대일이라는
보장이 없고 위치가 없으면 CHG-A07은 `원문 전체`를 보낸다. 관련 승인 항목 전체도
사용자가 지정한 수정 범위가 아니다. 항목 ID만으로 범위를 추론하거나 위치가 없는
경우 원문 전체를 선택하지 않는다.

## AI 내부 구현

`POST /v1/document-revisions`는 내부 토큰을 요구하며, 기존 `SourceInput`
스냅샷, `expected_document_version_id`, 비어 있지 않은 `selected_block_ids`,
`instruction`, `request_key`를 받는다. `agreements`와 `related_proposals`는
선택적 문자열 목록이다. 기존 AI-A06을 대체한다는 확정 계약이 아니라 별도 경로다.

AI는 원문을 다시 파싱하고 해시와 선택 ID를 확인한다. 모델에는 선택된 블록의
원문만 보낸다. 결과는 선택된 ID별 대체 본문·이유·선택적 근거만 허용하고, 알 수
없는 ID, 중복 ID, 잘못된 근거, 유효하지 않은 텍스트, 줄 경계를 침범하는 결과는
거절한다. 근거는 입력된 합의 또는 제안의 실제 문자열이어야 한다. 선택되지 않은
원문은 입력에서 그대로 이어 붙여 전체 초안을 만든다. 의미상 요청에 맞는지는
사람이 검토하며, 이 모듈은 저장·승인·발행하지 않는다. 범위가 없거나 현재
스냅샷에 없는 ID가 있으면 모델 호출 전에 거절한다.

Markdown은 결과를 재파싱해 선택 밖 블록의 구조와 제목·표·목록·참조 문맥을
비교하고 달라지면 모델 출력을 거절한다. 이 검사는 파서가 지원하는 구문 범위의
구조 검증이며 문서 내용의 의미적 정확성은 사람이 검토해야 한다.

응답은 `origin`, `model`, 실제 `usage`와 `result`를 포함한다. `result`에는
`document_version_id`, `after_content`, 각 변경의 `block_id`, `before`, `after`,
`reason`, `evidence`, 그리고 `unresolved`가 있다. 모델이 해결할 수 없으면 빈
`changes`와 이유를 반환할 수 있다. 호출자는 실제 현재 승인 버전을 읽고 모델
호출 후에도 변경되지 않았는지 재검사해야 한다. AI의 버전 비교는 요청 내부의
일치 여부만 확인하며 현재 승인본 조회를 대신하지 않는다.

## BE·FE 연계와 남은 확인

- 기존 CHG-A07은 유지하고 별도 scoped 경로로 블록 조회와 초안 생성을 연결한다.
  FE에서 기준 문서의 블록을 명시적으로 선택하고, 결과를 검토한 뒤 적용한다.
  범위 없는 요청을 전체 문서로 해석하지 않는다. 인덱스 청크 ID와 파서 블록 ID는
  서로 다른 식별자다.
- BE는 승인된 기준 문서를 조회해 AI에 전달하고, 호출 뒤 권한과 기준 버전을 다시
  확인한다. 모델 사용량과 오류도 기록한다. 실제 AI 서버까지 포함한 전체 흐름은
  통합 환경에서 추가 검증해야 한다.
- 선택된 블록은 전부 바뀔 수 있다. 더 세밀한 문자 범위, 항목과 블록 매핑,
  블록 경계 변경, 여러 문서 수정은 별도 계약이다.
- 화면에 항목별 전후·사유·근거를 표시한다. 합의와 관련 제안은 사용자가 직접
  입력한 참고 내용이며, 확정된 사실이나 검증된 출처임을 시스템이 보장하지 않는다.

## 대표 사례 검토

합성 문서의 가운데 문단에서 삭제 권한을 전체 사용자에서 팀장으로 바꾸는 사례를
가짜 모델로 실행했다. 선택한 문단만 바뀌고 앞뒤 문단은 그대로였으며, 전후 문장과
입력 합의의 인용이 반환됐다. 선택 없음, 다른 버전의 블록, 선택 밖 ID, 중복 변경,
없는 근거, 블록 경계의 줄바꿈 제거와 제어 문자를 거절하는 테스트도 통과했다.
2026-11-06 합성 문단으로 실제 모델을 호출했다. 모델이 줄 경계 LF를 포함한
대체문을 반환한 호출은 허용됐고, LF를 생략한 호출은 검증에서 거절됐다. 줄바꿈
보존 지시를 보완한 뒤 합성 사례 3회에서 선택 범위 밖 문자가 유지됐다.
실제 모델 출력이 항상 유효한 것은 아니므로 실패 처리가 필요하다. 이 검토는
한 합성 사례에 한정되며 실데이터 품질과 BE 연동 검증을 대신하지 않는다.
