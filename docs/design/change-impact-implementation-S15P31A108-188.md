# 설계 관계와 변경 영향 분석 구현 메모 (#188)

이 문서는 현재 브랜치의 구현과 연결되지 않은 부분을 구분한다. #195 변경 제안 생성, #197 결과 저장과 #167 관계 API의 계약이나 팀의 승인 절차를 변경하지 않는다.

## 현재 구현한 흐름

1. `DesignDependencyService`는 사람 팀장이 현재 승인 기준의 두 항목 버전에 대해 확인·해제한 관계 이력을 기록하고 조회한다. 호출 시 프로젝트·멤버 권한을 확인한다. 기존 `EXPLICIT` 및 AI 후보 행은 별도 승인 없이 확정 관계로 취급하지 않는다. 현재 서비스는 내부 전용이며 사용자에게 직접 관계를 확정하는 API가 아니다.
2. `ImpactContextQuery`는 승인 전 변경 제안, 그 기준 설계, 열린 작업의 현재 계획, 해당 기준에 확인된 관계를 프로젝트 범위로 읽는다. 제안의 기준이 현재 기준과 다르면 재분석이 필요하다.
3. `ImpactCandidateFinder`는 변경된 항목에 대한 직접 참조와 역방향 설계 의존 한 단계의 후보·경로를 만든다. 오래된 계획 참조를 표시하며 전체 관계의 완전성은 `UNKNOWN`이다. 후보만으로 작업 상태나 승인 여부를 바꾸지 않는다.
4. 변경 내용 키워드로 같은 프로젝트의 승인 설계와 열린 작업을 각각 최대 20건 추가 탐색한다. 명시 관계가 없는 항목도 AI 입력 후보로 넣되 관계를 자동 확정하지 않는다. 검색 상태와 잘림을 기록하며 벡터 검색이나 완전한 검색을 뜻하지 않는다.
5. `ImpactAnalysisCoordinator`는 입력을 AI-A03에 전달하고 응답의 ID·문서 출처를 입력과 대조한다. 다만 현재 V2는 변경안의 `schema_version`을 저장하지 않아 CREATE·UPDATE는 값을 추측하지 않고 AI 호출 전 미평가로 종료한다. 가능한 호출의 입력 변경 여부를 재확인하고, AI 실패 시 규칙 후보와 수신된 사용량을 반환한다. 통신이 끊겨 사용량을 받지 못한 경우는 `UNKNOWN`이다.
6. AI의 `POST /v1/impact`는 기존 공통 LLM 클라이언트를 사용한다. 근거 상태와 검증 후보 ID는 AI-A03에 추가한 **제안 필드**이며 BE·#197 저장 계약은 아직 확정되지 않았다.

## 연결해야 할 작업

- #195와 관계 승인 흐름: 변경 제안 생성·승인과 관계 확인 호출의 트랜잭션, 최초 기준 발행 전 확인 경로를 연결한다. 독립적인 확인 API로 승인 절차를 우회하지 않는다.
- #197: 규칙 경로, AI 후보, 불충분·실패 상태와 호출별 사용량을 저장한다. 결과를 저장하는 트랜잭션에서 기준·관계·계획을 다시 검사하고 적절히 잠가, AI 호출 후 저장 사이의 변경 경쟁을 막아야 한다. 현재 `requireUnchanged`만으로는 저장까지 원자적이지 않다.
- 관련 작업·원문 검색: 현재 제한된 키워드 검색만 추가했다. 동의어·표현 차이, 결과 상한 등으로 관련 작업이 누락될 수 있으며, 승인 원문 벡터 검색과 문서 항목·작업의 의미 연결은 아직 없다. 검색 실패·인덱스 미준비를 영향 없음으로 간주하지 않는다.
- 공개 조회·재분석 API, 사용량 DB 저장, UI 및 승인 후 CDC 동기화는 아직 연결되지 않았다.
- 관계 이력 스키마는 `backend/src/main/resources/db/ontology-draft/V8__design_dependency_confirmation.sql`에 보관한다. Flyway의 기본 경로 밖이므로 서버 시작 시 자동 적용되지 않고, 이 브랜치의 관계 서비스는 정식 마이그레이션 적용 전 운영 DB에서 사용할 수 없다. 통합 테스트 두 클래스만 별도 위치를 명시해 초안을 적용한다. 팀 합의 후 선행 migration 머지·DB 상태를 확인하고 최종 번호를 정해 기본 경로로 옮겨야 한다.

## 확인된 검증과 한계

백엔드의 규칙 계산·권한 단위 테스트와 AI 내부 API의 가짜 공급자 테스트가 있다. PostgreSQL을 사용하는 관계·영향 조회 통합 테스트는 작성했지만 Docker 엔진이 준비되지 않아 아직 실행하지 못했다. 실제 모델의 가상 사례는 [초기 평가](../../ai/evaluations/change_impact/results-2026-10-28.md)에서 필드 변경 출력 오류와 문구 변경 과잉 후보가 나왔다. [보완 후 평가](../../ai/evaluations/change_impact/results-2026-10-28-postfix.md)의 단일 실행에서는 네 사례의 형식과 기대 근거 상태가 맞았으나 반복 평가가 필요하다.
