# 에이전트(Claude Code) 연결 매뉴얼

로컬 Claude Code를 BEEZ에 연결해 승인 설계 조회·작업 계획·검증·상태 보고를 MCP로 쓰는 방법이다. 처음 연결하는 팀원이 이 문서만 보고 연결·확인·해제까지 할 수 있게 쓴다.

- 대상: 프로젝트 멤버 누구나. 토큰은 **나 + 이 프로젝트** 전용이다.
- 서버: dev는 `https://dev.beez.ai.kr`, MCP 주소는 `https://dev.beez.ai.kr/mcp`. 로컬 서버는 화면에 나오는 주소를 쓴다.
- 관련 요구사항: AGT-01(연결)·AGT-04(안내)·AGT-05(연결 확인)·AGT-06(해제). 계약은 [02-mcp-tools.md 연결과 인증](../api/02-mcp-tools.md#연결과-인증).

## 먼저 알아 둘 규칙 두 가지

1. **한 사람은 프로젝트마다 연결 하나만 살아 있다.** 토큰이 달라도(다른 PC·다른 터미널) 같은 계정이면 **나중 연결이 이긴다.** 먼저 붙어 있던 쪽은 다음 호출에서 409 `agent_session_replaced`를 받고 끊긴다. 다른 팀원의 연결은 건드리지 않는다.
2. **토큰 원문은 발급할 때 한 번만 보인다.** 놓쳤으면 폐기하고 새로 발급한다. 한 사람이 한 프로젝트에 가질 수 있는 폐기 안 된 토큰은 5개다.

## 1. 토큰 발급 (웹)

1. 웹에 로그인하고 연결할 프로젝트로 들어간다.
2. **설정 → 내 설정 → 에이전트**로 간다. 프로젝트 주소 끝에 `?settings=agent`를 붙여도 열린다.
3. **1 토큰 발급**에서 토큰 이름(기본 `내 Claude Code`, PC를 구분하려면 `회사 노트북` 등)을 넣고 **토큰 발급**을 누른다.
4. 바로 아래 **2 Claude Code에 BEEZ 추가**에 토큰이 들어간 명령이 나온다. 화면을 닫기 전에 **복사**한다.

## 2. Claude Code에 BEEZ 추가 (터미널)

작업할 저장소 폴더에서 복사한 명령을 실행한다. Git Bash·PowerShell 모두 같다.

```bash
claude mcp add --transport http beez https://dev.beez.ai.kr/mcp --header "Authorization: Bearer <토큰>"
```

- 이 명령은 **등록만 하고 끝난다.** 대화 창이 뜨지 않는 게 정상이다.
- 등록은 **명령을 실행한 폴더**에 걸린다(기본 범위 local). 다음 단계의 `claude`도 같은 폴더에서 켠다.
- 이미 `beez`라는 이름이 있으면 `claude mcp remove beez`로 지우고 다시 넣거나, 이름을 바꿔(`beez-dev`) 넣는다.

## 3. CLAUDE.md에 작업 절차 붙여넣기

웹의 **3 CLAUDE.md에 작업 절차 붙여넣기**에서 **CLAUDE.md 내용 복사**를 눌러 저장소의 `CLAUDE.md`에 붙인다. 계획 등록 → 검증 → 시작 → 변경 확인 → 완료 보고 순서를 에이전트가 따르게 하는 안내다(연결할 때 서버도 같은 글을 보낸다).

## 4. 연결 확인

같은 폴더에서 Claude Code를 켠다.

```bash
claude
```

대화 창에서:

1. `/mcp`를 입력해 `beez`가 connected인지 본다.
2. 이렇게 부탁한다.
   ```
   beez의 check_connection을 호출하고 결과를 그대로 보여 줘
   ```
   `"connected": true`와 내 `project_id`·`account_id`가 나오면 된다.
3. 웹 설정 왼쪽 메뉴 **에이전트** 옆 표시가 **연결됨**이면 된다(최근 2시간 안에 통신한 살아 있는 연결이 있다는 뜻. 아니면 '연결 미확인').

설정 → 에이전트 화면 위쪽 상태 줄과 **연결 확인** 버튼은 연결 현황 API(AGT-A05, S15P31A108-75 PR #211)가 배포된 뒤 동작한다. 그 전에는 상태 줄에 "연결 상태 확인은 준비 중이에요"가 나오니 위 메뉴 표시로 본다. 배포 뒤 상태 줄의 뜻:

| 표시 | 뜻 |
|---|---|
| 연결됨 | 최근 2시간 안에 통신한 살아 있는 연결이 있다. 맡은 작업 없이 쉬는 중이어도 연결됨이다 |
| 연결 미확인 | 연결은 살아 있지만 진행 중(IN_PROGRESS)인 작업을 맡은 채 30분 넘게 통신이 없다. 작업이 멈췄는지 Claude Code 창을 확인한다 |
| 연결 실패 | 연결 확인을 눌렀는데 살아 있는 연결이 없다. 아래 문제 해결을 본다 |
| 연결 끊김 | 2시간 넘게 통신이 없거나 세션이 끝났다. Claude Code를 다시 켜고 연결 확인을 누른다 |
| 연결 전 | 아직 연결한 적이 없다 |

## 5. 연결 해제

- 잠깐 멈출 때: Claude Code를 끄면 된다. 2시간이 지나면 웹에서 연결로 보지 않는다.
- 토큰을 더 쓰지 않을 때: 웹 설정 → 에이전트 → **내 토큰**에서 그 토큰을 **폐기**한다. 열려 있던 연결도 다음 호출부터 거부된다. 로컬 등록도 지운다.
  ```bash
  claude mcp remove beez
  ```

## 문제 해결

| 증상 | 원인 | 할 일 |
|---|---|---|
| 브라우저로 MCP 주소를 열었더니 `{"error":{"code":"unauthenticated",…}}` | 브라우저는 토큰을 보내지 않는다 | 정상이다. MCP 주소는 Claude Code가 토큰과 함께 부른다 |
| Claude Code가 `rejected the Authorization header` 또는 401 `unauthenticated` | 토큰이 비었거나 서버에 없는 값이다(복사 실수, 다른 서버에서 발급한 토큰) | 발급한 서버와 MCP 주소가 같은지, `Bearer `와 토큰 사이에 공백 한 칸인지 본다. 안 되면 새로 발급해 다시 등록한다 |
| 401 `token_revoked` (Claude Code는 위와 같은 문구로 보일 수 있다) | 그 토큰을 폐기했다 | 새 토큰을 발급해 다시 등록한다 |
| 409 `agent_session_replaced` | 같은 계정이 이 프로젝트에 **새로 연결**했다. 다른 PC·다른 터미널의 `claude`, **작업 중 다른 터미널에서 친 `claude mcp list`**(상태 확인도 새 연결이다)가 모두 해당한다 | 쓸 창 하나만 남기고 그 창에서 `/mcp` → `beez` → Reconnect. 작업 중에는 다른 터미널에서 `claude mcp list`를 치지 않는다 |
| 404 `not_found` (MCP 세션이 없다) | 연결이 닫혔거나 서버가 세션을 잊었다(마지막 호출 뒤 1~2시간 조용함·서버 재배포) | `/mcp` → `beez` → Reconnect(또는 Claude Code를 다시 켠다) |
| `claude mcp list`에 `beez`가 없다 | 다른 폴더에서 등록했다 | 등록한 폴더에서 `claude`를 켜거나, 이 폴더에서 다시 등록한다 |
| 토큰 발급이 안 된다(한도) | 폐기 안 된 토큰이 5개다 | 내 토큰에서 안 쓰는 토큰을 폐기한다 |
